# 知识分析业务化设计

## 1. 产品定义

知识分析把当前知识空间中已经发布、可以追溯的实体与关系，交给确定性的业务规则进行推演，发现原文没有直接写出、但能够由已有事实严格证明的新结论。

它服务于“制度适用范围、风险传导、依赖影响、流程合规和组织责任”等关系型判断，不替代文档摘要、知识问答、BI 统计或结构化数据计算。

## 2. 用户心智

普通用户的操作顺序应当是：

> 提出业务问题 → 确认知识是否准备好 → 设置判断条件 → 试运行并查看样例 → 保存并运行 → 核验结论与证据 → 加入知识库或撤回

页面不要求普通用户理解 Datalog、谓词、变量或 SPARQL。平台用“业务角色、关系和结论”承接用户输入，再把结构化规则交给 Semantica 校验和执行。

## 3. 信息架构

| 页面 | 用户任务 | 主要对象 |
|---|---|---|
| 分析任务 | 创建、运行和管理重复分析 | `AnalysisScenario`、`AnalysisRuleSet` |
| 发现结果 | 查看新结论、证据、变化和发布状态 | `InferenceRun`、`InferredFact`、`InferenceEvidence` |
| 规则库 | 维护可复用的专家判断规则 | `AnalysisRule`、`AnalysisRuleVersion` |
| 专业查询 | 对图谱执行受控查询或只读 SPARQL | `SavedGraphQuery`、`QueryRun` |

“分析任务”和“发现结果”是一级业务入口；“规则库”和“专业查询”是配置与专家工具。

## 4. 数据准备状态

系统按当前用户和知识空间实时计算：已发布文档、当前图谱版本、实体、已有关系、推导关系、带来源关系、关系词表、规则数量和最近运行。

阻断条件：

- 没有已发布实体；
- 没有已发布关系。

提醒条件：

- 没有已发布文档；
- 关系来源证据覆盖率较低；
- 没有当前图谱发布；
- 没有启用规则。

## 5. 五步分析向导

1. 业务问题：名称、问题、分类和模板。
2. 知识基础：当前空间真实实体类型、关系类型、数量、示例和证据覆盖。
3. 判断条件：用业务角色连接多条关系，再定义结论。
4. 规则检查：调用 Semantica 校验并对当前真实事实执行受控预演。
5. 保存运行：原子创建规则集、规则版本和分析场景，并创建真实异步推演任务。

向导草稿仅保存在浏览器内存；用户确认前不写入数据库。最终创建发生在一个数据库事务中，失败不会留下半成品。

## 6. 模板

模板是只读的规则草稿，不是推理结果。模板关系必须映射或确认到当前空间的真实关系词表后才能运行。

- 制度适用范围
- 供应商风险传导
- 项目和系统依赖影响
- 流程合规判断
- 组织责任关系
- 产品关联发现

## 7. 结果与变化

发现结果以业务结论为中心，运行记录作为筛选上下文。系统比较同一分析任务相邻成功运行，区分：

- 本次新发现；
- 仍然成立；
- 已失效；
- 证据或规则版本发生变化。

推演结果为零时，返回结构化诊断：没有已有关系、缺少指定关系、条件组合无交集、规则无效、范围不匹配或结果已经存在。

## 8. 发布语义

- 预览结果：保留结论与证据，但不进入当前正式图谱。
- 加入知识库：基于当前知识重新创建发布运行，成功后生成新的 FalkorDB 图谱版本。
- 撤回本次发布：使该运行发布的结论失效并生成新图谱版本，历史运行和证据不删除。

## 9. 能力边界

当前规则仅支持二元 Horn Clause 与 AND 条件。OR、NOT、数值比较、时间窗口和任意外部函数不在本轮伪装实现。金额、排名、同比和环比等问题由结构化语义查询负责。
