# 多轮知识问答测试报告

## 知识服务 UI/UX 升级复验（2026-08-31）

升级后的四轮真实对话分别产生 85、76、403、98 个 Harness/平台投影事件，共 662 个事件；引用数为 5、5、6、3。第二轮“它支持哪些数据源？”被真实改写为“NexusOne 支持哪些数据源？”，证明使用了持久化会话历史。浏览器刷新后问题、回答、引用、检索轨迹和执行过程均恢复。

浏览器真实停止第三轮长回答后，页面在 0.2 秒内进入 `cancelled`；关闭流产生的后续传输错误不会再形成矛盾的 `turn_failed`。点击重新生成后创建新 Turn，Agent 实际调用 `knowledge_search`、`knowledge_graph_query` 与 `knowledge_get_fragment`，602 个事件后完成回答并生成 8 条可点击引用。

右侧执行过程仅展示真实可核验事件、工具摘要、状态、时间戳和持续时间；“已思考 N 秒”从 `turn_started` 开始，在完成、失败或取消事件停止。没有展示或伪造模型私有 Chain-of-Thought、系统提示词、API Key 或内部凭据。

最终浏览器检查：1280×720、1440×900、1920×1080 均无页面横向溢出，输入框保持可见，三栏分别滚动；控制台 error/warning 为 0。引用 `[1]` 可将右栏切换到召回依据并定位第一名，打开真实 `m10-knowledge.txt` 片段。浏览器测试会话已通过产品接口删除。

测试使用真实 Kimi 默认 LLM、锁定版本 DeepSeek Harness、平台内部短期凭据和已发布的 `M10 系统验收` 知识空间。没有把一次 FastAPI 模型调用当作 Agent 适配；每轮都在 Harness Session 中产生 Turn/Step/Tool/Streaming 事件。

取消/重试测试中，生成被真实取消，助手消息状态为 `cancelled`；随后对同一消息重试，创建带 `retry_of` 的新助手消息并完成，收到 752 个 SSE 事件。并发测试的 5 个 Agent Session 全部完成。

恢复测试中，第一轮结束后重启 agent-runtime，第二轮“它的主要优势是什么？”仍明确回答 NexusOne，没有出现“没有可调取的上一轮”，同一 Harness Session JSONL 中存在至少 2 个 `turn/start`。最终镜像组合全栈冷启动前后两轮事件为 116/92（前一轮 164/135），会话映射和 Session ID 不变。

浏览器最终复验提问“NexusOne 的主要定位是什么？请给出真实引用。”，Harness 执行 `knowledge_search` 与 `knowledge_get_fragment`；页面显示：

- 点击 `[1]` 打开真实 `m10-knowledge.txt`，显示结构位置和完整片段。

结论：历史指代、工具调用、多步事件、流式回答、引用核验、取消、重试、页面/服务重启恢复均真实通过；证据不足或页码为空时会明确说明，不编造集团知识或页码。
