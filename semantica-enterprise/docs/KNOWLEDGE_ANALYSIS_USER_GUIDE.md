# 知识分析业务使用说明

## 这个模块解决什么问题

知识分析把当前知识空间内已经发布的对象、关系和来源证据，与业务人员定义的判断规则组合起来，发现原始材料没有直接写明、但能够由已有事实推出的新结论。每条结论都保留规则版本、前提关系、来源文档和知识图谱版本，因此可以核验、加入知识库或撤回。

它适合制度适用范围、供应商风险传导、项目依赖影响、流程合规判断和组织责任关系等关系推演。金额汇总、同比、排名等实时数值问题应使用结构化语义查询；文档内容查找和解释应使用知识服务。

## 推荐使用顺序

1. 在左侧选择本次工作的知识空间。
2. 进入“知识洞察 → 知识分析”。
3. 查看“数据准备情况”。至少需要已经发布的知识对象和关系；只有文档文本而没有关系时无法推演。
4. 点击“创建分析任务”，从业务问题或模板开始。
5. 在向导中确认真实实体类型、关系类型、数量、样例和来源覆盖率。
6. 用业务角色设置判断条件，查看自然语言预览。
7. 执行试运行，检查语义建模校验、匹配样例、预计结论和证据完整度。
8. 首次使用选择“预览结果”。确认发现结果和证据链后，再点击“加入知识库”。
9. 如结论不再适用，在发布运行上选择“撤回本次发布”。历史运行和证据不会删除。

## 分析任务

分析任务是普通用户的主要入口。一个任务表示需要持续回答的业务问题，并绑定知识空间、规则组和运行方式。

任务卡展示业务问题、判断规则数量、最近运行、新发现和当前状态。任务可以手工运行，也可以设置为新知识发布后自动重算；默认只生成待查看结果，不自动加入知识库。

### 五步向导

| 步骤 | 用户操作 | 系统真实处理 |
|---|---|---|
| 要分析什么 | 填写任务名称、业务问题、分类或选择模板 | 形成任务草稿，不改变正式知识 |
| 确认知识基础 | 查看并确认对象和关系 | 读取当前空间有效实体、已有关系和来源覆盖率 |
| 设置判断条件 | 用业务角色选择关系和结论 | 将业务角色安全映射为 Datalog 变量 |
| 试运行 | 查看校验、样例和预计结果 | 调用 Semantica DatalogReasoner 进行真实匹配 |
| 保存并运行 | 选择预览或加入知识库 | 原子创建规则组、规则版本、任务、运行和后台任务 |

结论中的角色必须在至少一个条件中出现。当前空间不存在的关系不能直接保存为可运行任务，页面会提示应补充知识或调整映射。

## 发现结果

发现结果首先呈现业务结论，并按“本次新发现、仍然成立、已失效”区分运行变化。选择一条结论后可以查看：

- 命中的业务规则和规则版本；
- 每一条推导前提；
- 前提对应的主体、关系和客体；
- 来源文档、页码或结构位置；
- 真实来源片段；
- 可信程度和发布状态。

“预览结果”不会改变正式知识；“加入知识库”会生成新的有效图谱版本；“撤回本次发布”会让本次发布的结论失效并生成后续图谱版本，不会删除历史记录。

当结果为零时，页面会根据真实规则和数据返回原因，例如缺少某个关系、多个条件无法连接到同一组对象、结论已经存在或证据不足，并提供查看关系、修改任务和补充知识的入口。

## 规则库

规则库用于复用和维护分析任务背后的业务判断逻辑。普通用户可完全通过任务向导创建规则；知识工程人员可以在规则库中校验、复制、编辑、停用和查看版本。

默认页面只显示自然语言规则。Datalog DSL 位于“技术信息”折叠区。版本记录同时展示变更前后的自然语言规则。仍被分析任务引用的规则组不能直接删除，需先删除任务或更换规则组。

## 专业查询

专业查询用于精确检查当前知识图谱：

- “普通查询”通过主体名称、关系类型、客体类型和是否包含推导结论生成受控 SPARQL；
- “SPARQL 编辑器”面向知识工程人员，支持只读查询、模板、保存、分页、复制和 CSV 导出。

关系 URI 在图谱投影中带有业务中文标签，因此可以通过 `rdfs:label` 按“适用于”等业务名称查询。查询始终限制在当前用户有权访问的知识空间。

## 验收空间

执行以下命令可幂等建立“知识分析验收空间”，不会删除其他空间或客户演示数据：

```bash
docker compose -f compose.yaml -f compose.structured-test.yaml run --rm --no-deps \
  -v "$PWD:/workspace" -w /workspace api \
  python tests/e2e/seed_knowledge_analysis_acceptance.py
```

验收空间包含两个可重复验证的场景：

| 场景 | 已有知识 | 预期发现 |
|---|---|---|
| 制度适用范围 | 采购管理制度适用于国联集团；国联集团管理数字科技公司 | 采购管理制度适用于数字科技公司 |
| 供应商风险传导 | 东方智造供应 NexusOne；NexusOne 用于智慧流程中枢项目；东方智造存在交付延期风险 | 智慧流程中枢项目受到交付延期影响 |

两份材料、7 个对象、5 条前提关系全部关联真实可打开的文档片段，来源证据覆盖率为 100%。
