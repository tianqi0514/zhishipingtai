# 国联集团业务用户旅程

## 1. 角色与工作目标

| 角色 | 首次进入系统的目标 | 日常主操作 | 不应看到或执行 |
|---|---|---|---|
| 系统管理员 | 建组织、用户、角色和全局配置 | 权限、模型、策略、审计 | 业务内容的日常维护不应成为必经步骤 |
| 集团知识管理员 | 建集团知识空间并接入权威资料 | 发布、治理、质量和版本 | 子企业私有空间的未授权内容 |
| 子企业知识管理员 | 管理本企业知识范围 | 接入、治理、授权和检索验证 | 其他子企业的私有知识 |
| 部门知识维护人员 | 维护被授权部门资料 | 上传、版本、治理任务 | 系统配置、应用凭据和全局权限 |
| 普通员工 | 查制度、产品和业务知识 | 检索、问答、引用查看、反馈 | 配置与发布按钮 |
| 应用开发人员 | 把稳定知识能力接入业务系统 | 应用、知识供给、场景、测试、凭据 | 数据库 Secret、平台内部工具凭据 |
| 只读审计人员 | 核验谁在何时使用和修改知识 | 审计、版本、QueryRun、引用 | 修改、发布和删除 |
| 应用服务账号 | 按最小权限调用已发布场景 | Token、场景调用、反馈 | 管理 API、数据库和检索中间件 |

## 2. 集团知识管理员主旅程

```text
确认组织与空间权限
→ 选择或创建数据源/上传文件
→ 查看同步任务和生成文档
→ 查看解析元素、画像和质量问题
→ 处理人工治理任务
→ 发布当前知识版本
→ 在检索、图谱和问答中验证
→ 创建知识供给版本给应用使用
```

每一步的完成状态必须能进入下一步；“同步成功”与“知识可检索”分别表示数据已取得和知识加工/发布已完成，页面不能混为一谈。

## 3. 普通员工主旅程

```text
选择有权访问的知识空间
→ 提问或检索
→ 查看回答、检索轨迹和排序依据
→ 点击引用核验原文
→ 继续追问
→ 对错误或低质量内容提交反馈
```

普通员工不需要理解 Chunk、RRF、Query IR 或发布清单；这些技术信息只在“回答依据/技术详情”中按需展示。

## 4. 数据管理员主旅程

```text
配置只读数据库连接
→ 发现 Schema
→ 实时预览与脱敏检查
→ 建本体映射并验证
→ 激活映射
→ 自然语言查询测试
→ 选择知识索引/实时查询/图谱物化
→ 验证时效与 Provenance
```

业务对应关系：表对应业务对象集合、行对应实体实例、字段对应属性、外键对应关系。本体描述“业务含义”，映射描述“业务含义如何落到当前数据库结构”。

## 5. 应用开发人员主旅程

```text
创建业务应用
→ 选择不可变知识供给
→ 创建能力场景版本
→ 建真实业务测试集并运行
→ 质量门禁通过
→ 授予最小范围
→ 创建一次可见的 Client Secret
→ 换取短期 Token 并调用
→ 查看调用审计
→ 将用户反馈转治理
→ 修复后重新评测
```

应用不绑定随时变化的空间列表，而是绑定知识产品 Release/别名；场景版本锁定检索策略、模型、工具白名单和引用策略。

## 6. 管理员首次进入引导判定

工作台需要根据真实状态给出下一步：

- 没有组织/用户：先完成组织初始化。
- 没有知识空间：创建知识空间并授权。
- 没有可用模型：配置 LLM/Embedding，未配置 Vision/ASR/Reranker 时显示降级。
- 有数据源但没有知识：进入同步任务或失败详情。
- 有文档但没有发布：进入加工/治理任务。
- 知识已发布：进入检索验证或应用构建。

该引导只能由后台真实数据计算，不能使用静态进度。
