# 传神智库 20 分钟演示脚本（菜单导览＋业务闭环版）

> **演示数据，不代表国联集团真实经营数据。** 本脚本复用现有“国联集团组织级知识底座演示空间”和已经加工完成的数据，不新建配置、不现场等待长任务。

## 一、演示目标

在 20 分钟内讲清三件事：

1. 左侧每个菜单处在集团知识建设流程的哪一步。
2. 一份制度、一个经营数据库和一条供应商风险，如何从数据接入走到治理、分析、问答和应用开放。
3. 用同一个问题真实对比“不使用图谱”和“使用图谱”，并展示图片、音频、视频如何成为带位置引用的知识。

演示账号已通过公开会话 API 准备四组真实历史会话；可重复执行
`scripts/demo/prepare_guolian_demo_conversations.py` 进行刷新。脚本会等待每轮
DeepSeek Harness SSE 完成，并校验消息、引用、工具事件和历史上下文后才返回成功。

统一业务主线：

> 集团需要依据采购制度，查询 NexusOne 的实时有效采购金额；同时，当东方智造发生交付延期时，需要判断会影响哪些产品、项目和责任部门，并核验每条结论的依据。

5. 演示前用当前平台真实运行并保留下列历史对话。现场只打开历史记录，不重新等待生成：
   - `演示01｜不使用图谱`：开启全文和向量，关闭图谱；
   - `演示02｜使用图谱增强`：开启全文、向量和图谱；
   - `演示03｜制度与经营数据`：包含制度口径与数据库金额的组合问题；

7. 把固定问题放入现场备忘，不要现场临时发挥：

8. 历史对话必须是系统此前真实执行的会话，不得把手工编写的答案或截图伪装为历史记录。
9. 本轮不现场上传大文件、不修改模型路由、不生成新的接入密钥。

> 操作建议：只在左侧依次展开或指向一级菜单，不要逐页加载全部子菜单。每项控制在 15～25 秒。

| 运营中心 | 运营概览、任务中心、能力检测 | 查看解析、同步、推演等长任务，以及模型和中间件状态 | “运营中心保证平台不是黑盒，任务卡在哪一步、哪项依赖不可用都能看见。” |

> “把这些菜单串起来，就是一条完整链路：数据先接入，成为知识资产；经过治理形成可信知识；通过知识服务被人和智能体使用；再通过应用构建进入具体业务，运营中心负责持续保障。”

## 六、真实业务闭环（3:30–18:30）

### 第一步：从数据库数据接入开始（3:30–5:45）

**角色：集团知识管理员**

**路径：数据接入 → 演示·国联经营数据 PostgreSQL**

#### 页面操作

1. 打开数据源详情，展示连接状态、最近结构发现时间和同步状态。
2. 进入“结构发现”，展示业务表、字段、主键和外键。
3. 进入“数据预览”，选择 `purchase_orders` 或采购订单相关表。
4. 展示服务端分页，并按 2026 年、有效状态或金额做一次受控筛选。
5. 打开一条字段详情，说明敏感字段由服务端隐藏或脱敏。
6. 切到“语义映射”，展示采购订单、供应商、产品、项目等业务对象已映射到真实表和字段。

#### 演示话术

> “数据库接入后，平台不会先把整张表塞给大模型。系统先发现 Schema，识别表、字段、主外键，再把物理结构映射成采购订单、供应商、产品等业务语义。浏览器拿不到数据库密码，查询值使用参数绑定，敏感字段在服务端处理。”

#### 必须看到

- 真实 PostgreSQL 数据，而不是静态截图。
- 数据来源标记为“实时数据库”。
- 表、主键、外键和当前映射状态。
- 页面不显示数据库密码或完整连接串。

### 第二步：演示 Text-to-SQL 实时问数（5:45–7:15）

**路径：数据接入 → 查询测试**

#### 页面操作

输入：

> `2026 年 NexusOne 相关有效采购金额是多少？`

依次展开：

1. 识别到的业务对象和统计口径；
2. Semantic Query Plan；
3. 严格 Query IR；
4. 后端编译出的参数化只读 SQL；
5. 真实执行结果与数据时间。

#### 演示话术

> “这不是让模型自由生成一段 SQL。模型只能描述要查什么业务对象、如何筛选和聚合；平台用已经激活的语义映射生成严格 IR，再确定性编译 MySQL 或 PostgreSQL SQL，最后在权限、只读、超时和行数限制下执行。”

#### 预期结果

- NexusOne 相关有效采购金额：**600,000 元**。
- 取消订单和未满足有效口径的数据不计入。
- 页面显示查询时间、映射版本、Schema 版本和 QueryRun。

### 第三步：查看这项数据对应的知识资产（7:15–8:30）

**路径：知识资产 → 文档资产**

#### 页面操作

1. 打开《集团本部采购实施细则（2025演示现行版）》。
2. 展示原始内容预览、当前版本、自动摘要、分类、标签和质量画像。
3. 定位“有效采购金额”和“采购目标完成率”的统计口径。
4. 快速展示同一空间还包含 PDF、扫描件、图片、邮件、音频和视频；此处只说明已完成加工，具体识别结果在后面的历史对话中打开。

#### 演示话术

> “数据库告诉我们金额是多少，制度文档告诉我们这个金额应该按什么口径计算。知识资产保留原文、版本和结构位置；扫描件、图片和音视频也会分别通过 OCR、视觉理解和 ASR 进入统一知识结构。”

#### 必须看到

- 现行制度文档内容可正常预览、无乱码。
- 文档具有治理画像和来源位置。
- Markdown 显示为文本解析结果，不讲成 OCR。

### 第四步：从原始知识到可信关系和新结论（8:30–10:45）

**角色：集团业务知识专员**

**路径：知识治理 → 治理概览／知识图谱／规则推演**

#### 页面操作

1. 在治理概览快速指出制度版本、重复内容、组织别名或 OCR 质量等治理问题。
2. 进入知识图谱，搜索“东方智造”。
3. 沿关系展示：
   - 东方智造 → 供应 → NexusOne；
   - NexusOne → 用于 → 智慧流程中枢项目；
   - 责任组织 → 负责 → 智慧流程中枢项目。
4. 点击一条边，打开来源文档或片段。
5. 进入规则推演，打开“供应商风险传导”分析任务和发现结果。
6. 展示规则：供应商供应产品、产品用于项目、供应商存在风险，则项目受到该风险影响。
7. 展开推导结论的三项前提和证据链。

#### 演示话术

> “治理不是简单改标签。平台把文档中的对象和关系标准化，并允许业务人员处理版本、别名和错误关系。图谱解决跨文件关联；规则推演则把集团专家经验固化成可重复执行的判断。正式推导由 Semantica Datalog 完成，不是大模型猜出一个结论。”

#### 必须看到

- 白底知识图谱及真实节点、边。
- 每一跳关系可以打开来源。
- 供应商风险推演结果具有规则、前提、来源和版本。

### 第五步：同一个问题，对比不使用图谱和使用图谱（10:45–13:00）

**角色：集团普通业务用户**

**路径：知识服务 → 智能问答 → 历史会话**

#### 固定问题

两个历史会话都使用：

> `东方智造的交付延期会影响哪些项目和责任部门？请说明完整路径和依据。`

#### A. 不使用图谱

1. 打开历史会话“演示01｜不使用图谱”。
2. 展示该轮设置：全文开启、向量开启、图谱关闭、重排关闭，Top K 与第二组一致。
3. 展示已经生成的回答，不重新发送。
4. 打开右侧“检索轨迹”，明确图谱召回数为 0。
5. 打开“召回依据”，说明系统主要找到与东方智造、延期、NexusOne 或项目语义相近的原文片段。

话术：

> “关闭图谱后，系统仍能通过关键词和语义相似度找到相关材料。它擅长回答原文写了什么，但当供应商、产品、项目和责任部门分散在不同文件中时，模型需要依赖有限片段自行组织，不能保证得到完整、可验证的关系路径。”

#### B. 使用图谱增强

1. 切换历史会话“演示02｜使用图谱增强”。
2. 展示该轮设置：全文、向量、图谱均开启，重排关闭，其余条件与第一组相同。
3. 展示已经生成的回答，不重新发送。
4. 打开“检索轨迹”，确认图谱通道确实返回结果。
5. 打开“召回依据”，指出带有图谱通道的召回项。
6. 展示回答中的关系路径：东方智造 → NexusOne → 智慧流程中枢项目 → 相关责任组织。
7. 点击其中一条引用，核验每一跳对应的文档、邮件或推演证据。

话术：

> “打开图谱后，问题没有变，全文和向量参数也没有变。新增的是沿已发布关系进行扩展：从供应商找到产品，从产品找到项目，再定位责任组织。图谱不是替代原文，而是补充跨文档的关联范围；最后仍由原始片段和推演证据证明每一跳。”

#### 现场对比结论

| 对比项 | 不使用图谱 | 使用图谱增强 |
|---|---|---|
| 主要能力 | 找关键词和语义相近片段 | 在原文召回基础上扩展实体关系 |
| 跨文件关联 | 取决于召回片段是否碰巧同时覆盖 | 可以沿已发布关系寻找多跳对象 |
| 回答表现 | 更适合概括直接命中的材料，可能只覆盖片段中明确出现的对象 | 更适合列出供应商、产品、项目、责任组织之间的完整影响路径 |
| 结果解释 | 以文档片段为主 | 同时展示关系路径和逐跳来源 |
| 适合问题 | 制度条款、定义、原文说明 | 影响范围、上下游、责任链、依赖关系 |

如果两组回答文字接近，必须如实说明：

> “这次原文召回本身已经覆盖了较多事实，所以答案文字可能接近；图谱的增量价值体现在图谱通道真实参与、关系路径明确、跨文档节点可以稳定扩展，而不是刻意让关闭图谱的答案变差。”

### 第六步：用历史对话展示制度、数据库和多模态（13:00–17:00）

**角色：集团普通业务用户**

**路径：知识服务 → 智能问答 → 历史会话**

打开“演示03｜制度与经营数据”，定位历史问题：

> `按照采购制度规定的统计口径，2026 年 NexusOne 相关有效采购金额是多少？`

页面操作：

1. 直接展示历史回答，不现场重新生成。
2. 在右侧“执行过程”查看该轮真实调用过知识检索和结构化查询工具。
3. 在“检索轨迹”查看制度检索与数据库查询阶段。
4. 在“召回依据”分别打开制度引用和数据引用。
5. 展示数据引用中的数据源、查询时间、映射版本、Schema 版本和参数化 SQL 摘要。

预期：

- 回答为 **600,000 元**。
- 同时出现制度文档引用和结构化数据引用。
- 历史会话刷新后仍然存在，证明会话、消息、轨迹和引用已经持久化。

话术：

> “制度文档说明统计口径，实时数据库负责计算金额。历史对话保留的不只是最终文字，还包括当时调用过哪些工具、检索了哪些知识、执行了哪次受控查询以及引用了哪些来源。”

#### 历史会话二：多模态项目风险（15:00–17:00）

打开“演示04｜多模态项目风险”。该历史会话提前真实完成以下连续问题：

1. `项目总体架构图展示了哪些系统组件，它们之间是什么关系？`
2. `项目例会中提到了什么交付风险，哪个部门需要采取行动？`
3. `结合刚才的风险，视频中展示的哪个建设阶段可能受到影响？`

页面操作：

1. 打开第一轮的图片引用，展示 OCR 文本和视觉描述是两类独立结果。
2. 打开第二轮的音频引用，展示真实 ASR 文本和时间区间。
3. 打开第三轮的视频引用，展示音轨转写、关键帧和帧时间点。
4. 指出第三轮中的“刚才的风险”来自同一历史会话的前文，不是三个互不关联的单次问答。
5. 在右侧执行过程确认该历史轮次真实读取了相应知识片段。

话术：

> “多模态不是把音视频当附件保存。图片保留 OCR 和视觉理解，音频引用可以定位到具体时间，视频同时保留音轨转写和关键帧。第三个问题使用了上一轮的风险上下文，说明平台保存并恢复的是完整多轮会话，而不是只保存一段最终答案。”

边界说明：

- 不把 OCR 文本说成视觉理解结果。
- 不把视频旁白稿说成 ASR 结果。
- 不根据声音猜测真实说话人身份。
- 如果某次识别存在“东方制造/东方智造”等偏差，应展示原始转写与治理后的标准名称，不静默改写。

### 第七步：把知识能力交付给业务应用（17:00–18:00）

**路径：应用构建 → 应用工作台**

#### 页面操作

打开现有演示应用，指向四步上线流程：

1. 选择正式知识供给；
2. 配置问答、检索或分析能力场景；
3. 使用标准问题完成上线测试；
4. 通过接入发布向业务系统开放最小权限凭据。

再指向“运行反馈”：线上出现错误引用或过期知识后，可以转回治理工作台修复并重新测试。

#### 演示话术

> “底座建设完成后，不需要每个应用重新接一次文档和数据库。采购助手、制度助手或风控助手可以选择同一份正式知识供给，通过质量门禁后，以 REST、MCP 或 CLI 接入；运行问题再回到治理形成闭环。”

### 第八步：运营确认（18:00–18:30）

**路径：运营中心 → 任务中心或能力检测**

#### 页面操作

快速展示当前没有运行中或异常任务，并说明上传、同步、OCR、向量化、图谱发布和规则推演都有真实阶段与百分比。

#### 演示话术

> “运营中心让平台具备持续运行能力。某个任务慢在哪里、失败在哪个依赖、是否可以重试，都通过真实任务状态显示，而不是一直停留在一个虚假进度。”

## 七、总结（18:30–20:00）

### 收束话术

> “这条业务链从一个数据库和一份制度开始。数据接入让平台读懂来源，知识资产保留原文和版本，知识治理形成可信对象、关系和推导结论，知识服务把文档、数据库和图谱组合成可核验回答，应用构建再把能力交付给采购、风控等具体场景。整个过程共用同一套知识空间、权限、版本、来源和审计，这就是组织级知识底座与普通文档问答工具的核心区别。”

### 最后留给客户的三个结论

1. **数据不只被存储，而是被治理成可理解、可调用、可追溯的知识。**
2. **不同问题由不同能力处理：原文用检索，关系用图谱，规则用推演，实时数值用安全结构化查询。**
3. **底座能力可以通过应用构建和标准接口被集团后续业务场景复用。**

## 八、现场时间不足时的剪裁顺序

如果现场只剩 15 分钟，按以下顺序剪裁：

1. 菜单导览从 3 分钟压缩到 2 分钟。
2. 知识资产只打开现行制度，不浏览全部格式。
3. 治理概览只讲一个版本问题。
4. 图谱对比只展示两组历史回答和检索轨迹，不逐条打开全部召回卡片。
5. 多模态只打开一个音频时间引用和一个视频关键帧。
6. 应用构建与运营中心合并为 45 秒口头说明。

不得剪掉：

- “演示数据”声明；
- 600,000 元真实数据库结果；
- 文档与数据双引用；
- 同一问题关闭/开启图谱的真实对比；
- 至少一个音频时间引用或视频关键帧；
- “模型不能直接执行任意 SQL”和“推导不是大模型生成”的边界。

## 九、故障时的现场处理

| 情况 | 处理方式 |
|---|---|
| 大模型暂时不可用 | 继续展示数据库预览、查询测试、检索调试和图谱；明确问答当前不可用，不用预设答案替代 |
| 数据库不可用 | 展示文档、治理、图谱和推演；不要用 CSV 快照冒充实时查询 |
| 图谱通道不可用 | 展示全文和向量的真实降级结果，明确当前无法给出完整多跳路径 |
| Reranker 未配置 | 明确使用 RRF 融合，不展示虚构的重排分数 |
| 音视频历史会话缺少引用 | 不现场伪造或重新上传大文件；明确该环节未就绪，跳过多模态段并继续数据库、图谱和治理主线 |
| 页面加载较慢 | 等待真实加载状态，不连续重复点击；优先使用已经预检通过的固定业务路径 |
