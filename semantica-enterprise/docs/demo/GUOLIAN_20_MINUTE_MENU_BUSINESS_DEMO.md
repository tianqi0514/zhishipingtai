# 传神智库 20 分钟演示脚本（菜单导览＋业务闭环版）

> **演示数据，不代表国联集团真实经营数据。** 本脚本复用现有“国联集团组织级知识底座演示空间”和已经加工完成的数据，不新建配置、不现场等待长任务。

## 一、演示目标

在 20 分钟内讲清两件事：

1. 左侧每个菜单处在集团知识建设流程的哪一步。
2. 一份制度、一个经营数据库和一条供应商风险，如何从数据接入走到治理、分析、问答和应用开放。

统一业务主线：

> 集团需要依据采购制度，查询 NexusOne 的实时有效采购金额；同时，当东方智造发生交付延期时，需要判断会影响哪些产品、项目和责任部门，并核验每条结论的依据。

## 二、时间安排

## 三、演示前准备（不计入现场时间）

1. 打开 `http://localhost:8080/`，登录“集团知识管理员”演示账号。
2. 在左侧顶部确认当前知识空间为“国联集团组织级知识底座演示空间”。
3. 确认工作台显示：正在处理 0、异常任务 0。
4. 提前打开并确认以下内容可用：
   - 数据源“演示·国联经营数据 PostgreSQL”；
   - 现行制度《集团本部采购实施细则（2025演示现行版）》；
   - 图谱中的“东方智造”“NexusOne”“智慧流程中枢项目”；
   - 供应商风险规则推演结果；
   - 智能问答能够返回文档引用和数据引用。
5. 把两个固定问题放入现场备忘，不要现场临时发挥：
   - `按照采购制度规定的统计口径，2026 年 NexusOne 相关有效采购金额是多少？`
   - `东方智造的交付延期会影响哪些项目和责任部门？请说明完整路径和依据。`
6. 本轮不现场上传大文件、不修改模型路由、不生成新的接入密钥。

## 四、开场（0:00–0:40）

### 页面操作

登录后停留在“工作台”，确认演示空间名称显示正确。

### 演示话术

> “今天使用的都是专门构造的演示数据，不代表国联集团真实经营数据。我们重点展示的不是一个只会搜索文件的 RAG 工具，而是一套组织级知识底座：文档、数据库和多模态内容统一接入，经过治理形成可引用的知识，再通过检索、图谱、规则推演和数据库实时查询服务员工与智能体。”

## 五、一级菜单导览（0:40–3:30）

> 操作建议：只在左侧依次展开或指向一级菜单，不要逐页加载全部子菜单。每项控制在 15～25 秒。

| 一级菜单 | 页面中包含什么 | 在真实业务中的作用 | 建议话术 |
|---|---|---|---|
| 工作台 | 资产数量、最近文档、任务动态、异常提醒、下一步建议 | 判断当前知识空间是否健康、接下来该处理什么 | “工作台是每天进入平台后的总入口，先看资产、任务和异常，再进入具体工作。” |
| 知识资产 | 空间与目录、文档资产 | 确定知识边界，管理文件、版本、解析内容和治理画像 | “知识资产回答的是：集团现在有哪些知识、属于哪个空间、当前有效版本是什么。” |
| 数据接入 | 文件与外部数据源、数据库结构发现、实时预览、语义映射、查询测试 | 把文档库、网站、数据库等来源接入同一底座 | “数据接入负责把知识带进来；数据库既可以同步形成知识，也可以不经过同步直接做受控实时查询。” |
| 知识治理 | 治理概览、内容治理、知识图谱、规则推演、发布记录 | 处理版本、重复、别名、质量和关系，把原始内容变成可信知识 | “知识治理负责决定哪些内容可信、哪些版本有效、对象之间有什么关系，以及规则能推导出什么新结论。” |
| 知识服务 | 智能问答、检索调试、服务开放 | 面向员工提供问答，面向系统和智能体提供 REST、MCP、CLI | “知识服务是知识的使用出口，回答不仅要生成文字，还要显示检索轨迹、召回依据和真实引用。” |

| 运营中心 | 运营概览、任务中心、能力检测 | 查看解析、同步、推演等长任务，以及模型和中间件状态 | “运营中心保证平台不是黑盒，任务卡在哪一步、哪项依赖不可用都能看见。” |
| 配置中心 | 模型服务与路由、解析、媒体、加工策略、知识结构 | 统一管理模型和处理策略，避免配置散落在各模块 | “配置中心定义平台怎么处理知识，不是普通业务人员每天都要操作的页面。” |
| 系统管理 | 组织、用户、角色权限、审计日志 | 建立集团分级组织、知识空间权限和操作追溯 | “系统管理解决谁能看、谁能改、谁调用过的问题。” |

### 菜单导览收束话术

> “把这些菜单串起来，就是一条完整链路：数据先接入，成为知识资产；经过治理形成可信知识；通过知识服务被人和智能体使用；再通过应用构建进入具体业务，运营中心负责持续保障。”

## 六、真实业务闭环（3:30–18:30）

### 第一步：从数据库数据接入开始（3:30–6:30）

**角色：集团知识管理员**

**路径：数据接入 → 演示·国联经营数据 PostgreSQL**

#### 页面操作

1. 打开数据源详情，展示连接状态、最近结构发现时间和同步状态。
2. 进入“结构发现”，展示业务表、字段、主键和外键。
3. 进入“数据预览”，选择 `purchase_orders` 或采购订单相关表。
4. 展示服务端分页，并按 2026 年、有效状态或金额做一次受控筛选。
5. 打开一条字段详情，说明敏感字段由服务端隐藏或脱敏。
6. 切到“语义映射”，展示采购订单、供应商、产品、项目等业务对象已映射到真实表和字段。

#### 演示话术

> “数据库接入后，平台不会先把整张表塞给大模型。系统先发现 Schema，识别表、字段、主外键，再把物理结构映射成采购订单、供应商、产品等业务语义。浏览器拿不到数据库密码，查询值使用参数绑定，敏感字段在服务端处理。”

#### 必须看到

- 真实 PostgreSQL 数据，而不是静态截图。
- 数据来源标记为“实时数据库”。
- 表、主键、外键和当前映射状态。
- 页面不显示数据库密码或完整连接串。

### 第二步：演示 Text-to-SQL 实时问数（6:30–8:30）

**路径：数据接入 → 查询测试**

#### 页面操作

输入：

> `2026 年 NexusOne 相关有效采购金额是多少？`

依次展开：

1. 识别到的业务对象和统计口径；
2. Semantic Query Plan；
3. 严格 Query IR；
4. 后端编译出的参数化只读 SQL；
5. 真实执行结果与数据时间。

#### 演示话术

> “这不是让模型自由生成一段 SQL。模型只能描述要查什么业务对象、如何筛选和聚合；平台用已经激活的语义映射生成严格 IR，再确定性编译 MySQL 或 PostgreSQL SQL，最后在权限、只读、超时和行数限制下执行。”

#### 预期结果

- NexusOne 相关有效采购金额：**600,000 元**。
- 取消订单和未满足有效口径的数据不计入。
- 页面显示查询时间、映射版本、Schema 版本和 QueryRun。

### 第三步：查看这项数据对应的知识资产（8:30–10:00）

**路径：知识资产 → 文档资产**

#### 页面操作

1. 打开《集团本部采购实施细则（2025演示现行版）》。
2. 展示原始内容预览、当前版本、自动摘要、分类、标签和质量画像。
3. 定位“有效采购金额”和“采购目标完成率”的统计口径。
4. 快速展示同一空间还包含 PDF、扫描件、图片、邮件、音频和视频。

#### 演示话术

> “数据库告诉我们金额是多少，制度文档告诉我们这个金额应该按什么口径计算。知识资产保留原文、版本和结构位置；扫描件、图片和音视频也会分别通过 OCR、视觉理解和 ASR 进入统一知识结构。”

#### 必须看到

- 现行制度文档内容可正常预览、无乱码。
- 文档具有治理画像和来源位置。
- Markdown 显示为文本解析结果，不讲成 OCR。

### 第四步：从原始知识到可信关系和新结论（10:00–13:30）

**角色：集团业务知识专员**

**路径：知识治理 → 治理概览／知识图谱／规则推演**

#### 页面操作

1. 在治理概览快速指出制度版本、重复内容、组织别名或 OCR 质量等治理问题。
2. 进入知识图谱，搜索“东方智造”。
3. 沿关系展示：
   - 东方智造 → 供应 → NexusOne；
   - NexusOne → 用于 → 智慧流程中枢项目；
   - 责任组织 → 负责 → 智慧流程中枢项目。
4. 点击一条边，打开来源文档或片段。
5. 进入规则推演，打开“供应商风险传导”分析任务和发现结果。
6. 展示规则：供应商供应产品、产品用于项目、供应商存在风险，则项目受到该风险影响。
7. 展开推导结论的三项前提和证据链。

#### 演示话术

> “治理不是简单改标签。平台把文档中的对象和关系标准化，并允许业务人员处理版本、别名和错误关系。图谱解决跨文件关联；规则推演则把集团专家经验固化成可重复执行的判断。正式推导由 Semantica Datalog 完成，不是大模型猜出一个结论。”

#### 必须看到

- 白底知识图谱及真实节点、边。
- 每一跳关系可以打开来源。
- 供应商风险推演结果具有规则、前提、来源和版本。

### 第五步：用一次问答组合制度、数据库和图谱（13:30–17:00）

**角色：集团普通业务用户**

**路径：知识服务 → 智能问答**

#### 问题一：制度＋数据库

输入：

> `按照采购制度规定的统计口径，2026 年 NexusOne 相关有效采购金额是多少？`

操作：

1. 观察中间区域流式回答。
2. 在右侧“执行过程”查看 Agent 真实调用知识检索和结构化查询工具。
3. 切到“检索轨迹”，查看实际查询空间、召回通道和耗时。
4. 切到“召回依据”，分别打开制度引用和数据库引用。

预期：

- 回答为 **600,000 元**。
- 同时出现制度文档引用和结构化数据引用。
- 数据引用能够看到数据源、查询时间、映射版本和参数化 SQL 摘要。

#### 问题二：图谱＋规则推演

输入：

> `东方智造的交付延期会影响哪些项目和责任部门？请说明完整路径和依据。`

预期：

- 找到东方智造、NexusOne、智慧流程中枢项目和相关责任组织。
- 显示供应商→产品→项目的关系路径。
- 引用原始文档、邮件或推演证据，而不是只给一个结论。

#### 演示话术

> “同一个问题可能需要不同工具：制度口径来自文档，实时金额来自数据库，跨文件影响范围来自图谱，规则发现来自可证明的推演。DeepSeek Harness 负责在一次多轮会话中编排这些工具，FastAPI 仍然负责身份、权限、查询和数据访问。右侧展示的是可核验执行过程，不是模型私有思维链。”

### 第六步：把知识能力交付给业务应用（17:00–18:00）

**路径：应用构建 → 应用工作台**

#### 页面操作

打开现有演示应用，指向四步上线流程：

1. 选择正式知识供给；
2. 配置问答、检索或分析能力场景；
3. 使用标准问题完成上线测试；
4. 通过接入发布向业务系统开放最小权限凭据。

再指向“运行反馈”：线上出现错误引用或过期知识后，可以转回治理工作台修复并重新测试。

#### 演示话术

> “底座建设完成后，不需要每个应用重新接一次文档和数据库。采购助手、制度助手或风控助手可以选择同一份正式知识供给，通过质量门禁后，以 REST、MCP 或 CLI 接入；运行问题再回到治理形成闭环。”

### 第七步：运营确认（18:00–18:30）

**路径：运营中心 → 任务中心或能力检测**

#### 页面操作

快速展示当前没有运行中或异常任务，并说明上传、同步、OCR、向量化、图谱发布和规则推演都有真实阶段与百分比。

#### 演示话术

> “运营中心让平台具备持续运行能力。某个任务慢在哪里、失败在哪个依赖、是否可以重试，都通过真实任务状态显示，而不是一直停留在一个虚假进度。”

## 七、总结（18:30–20:00）

### 收束话术

> “这条业务链从一个数据库和一份制度开始。数据接入让平台读懂来源，知识资产保留原文和版本，知识治理形成可信对象、关系和推导结论，知识服务把文档、数据库和图谱组合成可核验回答，应用构建再把能力交付给采购、风控等具体场景。整个过程共用同一套知识空间、权限、版本、来源和审计，这就是组织级知识底座与普通文档问答工具的核心区别。”

### 最后留给客户的三个结论

1. **数据不只被存储，而是被治理成可理解、可调用、可追溯的知识。**
2. **不同问题由不同能力处理：原文用检索，关系用图谱，规则用推演，实时数值用安全结构化查询。**
3. **底座能力可以通过应用构建和标准接口被集团后续业务场景复用。**

## 八、现场时间不足时的剪裁顺序

如果现场只剩 15 分钟，按以下顺序剪裁：

1. 菜单导览从 3 分钟压缩到 2 分钟。
2. 知识资产只打开现行制度，不浏览全部格式。
3. 治理概览只讲一个版本问题。
4. 保留数据库 Text-to-SQL、图谱风险路径和组合问答，不能剪掉引用核验。
5. 应用构建与运营中心合并为 45 秒口头说明。

不得剪掉：

- “演示数据”声明；
- 600,000 元真实数据库结果；
- 文档与数据双引用；
- 图谱关系路径和来源；
- “模型不能直接执行任意 SQL”和“推导不是大模型生成”的边界。

## 九、故障时的现场处理

| 情况 | 处理方式 |
|---|---|
| 大模型暂时不可用 | 继续展示数据库预览、查询测试、检索调试和图谱；明确问答当前不可用，不用预设答案替代 |
| 数据库不可用 | 展示文档、治理、图谱和推演；不要用 CSV 快照冒充实时查询 |
| 图谱通道不可用 | 展示全文和向量的真实降级结果，明确当前无法给出完整多跳路径 |
| Reranker 未配置 | 明确使用 RRF 融合，不展示虚构的重排分数 |
| 音视频尚未加工完成 | 本脚本主线不依赖现场音视频处理，只展示已完成的资产状态 |
| 页面加载较慢 | 等待真实加载状态，不连续重复点击；优先使用已经预检通过的固定业务路径 |
