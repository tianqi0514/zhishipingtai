## 3. 数据库数据源

演示使用独立 MySQL 和 PostgreSQL，禁止连接平台自身业务库。两个方言使用同一业务 Ground Truth。

| 表 | 业务对象 | 关键关系/字段 | 演示点 |
|---|---|---|---|
| `org_units` | 组织单位 | 主键、单位名称 | 组织分组与目标归属 |
| `departments` | 部门 | 所属组织外键 | 责任部门 |
| `suppliers` | 供应商 | 主键、统一编码、敏感字段 | 别名、脱敏、无订单供应商 |
| `supplier_contacts` | 供应商联系方式 | 供应商外键、手机、邮箱、Token 样式字段 | 服务端脱敏、禁止字段不可预览或筛选 |
| `products` | 产品 | 产品编码、名称 | NexusOne、智慧流程引擎 |
| `projects` | 项目 | 负责组织/部门 | 智慧流程中枢项目 |
| `project_products` | 项目产品关联 | 项目与产品外键 | 多对多、图谱关系 |
| `purchase_orders` | 采购订单 | 组织、供应商、金额、状态、日期 | 实时金额、状态过滤 |
| `purchase_order_items` | 订单明细 | 订单与产品外键 | Join 去重、防止订单头重复累计 |
| `approval_records` | 审批记录 | 订单外键、审批决定 | 统计口径和合规异常 |
| `contracts` | 合同 | 供应商、订单 | 合同关联 |
| `risk_events` | 风险事件 | 供应商、产品、等级、日期 | 风险数量和影响项目 |
| `procurement_targets` | 采购目标 | 单位、年度、目标金额 | 目标完成率分母 |
| `system_dependencies` | 系统依赖 | 上游、下游、组件 | 多跳影响链 |
| `policy_applicability` | 制度适用范围 | 制度与组织 | 确定性图谱映射 |
| `archived_projects` | 历史项目空表 | 主键、文本字段 | 真实空表状态 |
| `procurement_order_overview` | 采购订单视图 | **无主键**；订单、组织、供应商汇总字段 | 无主键分页稳定性 Warning；只预览/查询，不稳定物化 |

国联演示业务域包含上表列出的 **16 张基础表和 1 个无主键视图**；复用的结构化测试 Fixture 还包含通用基准对象，不应把 SQL 文件中的全部对象数直接当作国联演示页面数量。2026-09-06 最终预检已确认两库均发现 16 张演示业务表，并分别找到 `procurement_order_overview` 无主键对象、返回稳定性 Warning；空表、真实行预览和服务端敏感字段保护也均为 2/2。

固定口径：2026 年有效采购额为 1,700,000 元；NexusOne 为 600,000 元；年度目标为 2,100,000 元；目标完成率为 80.95%；审批待补充但已执行订单 1 笔；高风险事件 2 起、去重供应商 1 家。

## 4. 安全与数据治理标识

- 演示邮箱使用 `example.invalid`，不得外发。
- 密码、Token、API Key、私钥字段禁止预览；手机号、证件、银行卡和邮箱在服务端脱敏。
- 原始客户 ZIP 仅做格式、编码、敏感性检查；演示上传使用本目录的合成/脱敏素材。
- ASR 实测会把“东方智造”转写成“东方制造”。这是**真实识别偏差**，演示时作为“自动结果 → 别名候选 → 人工确认标准名称 → 保留原转写”的治理案例，不能在转写层伪造正确文本。
- 每份素材上传后均应带 `国联集团演示`、`组织级知识底座`、`演示数据` 标签。
