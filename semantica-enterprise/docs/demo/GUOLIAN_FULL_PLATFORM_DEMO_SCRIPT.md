# 传神智库：国联集团组织级知识底座完整演示脚本

> **演示数据，不代表国联集团真实经营数据。** 演示中的组织、供应商、项目、金额和事件均为确定性构造数据。页面结果必须来自当前环境真实接口，未通过预检的环节不得口头宣称已完成。

## 1. 演示目标

用一条完整业务链证明：传神智库不是“上传文件后做一次 RAG”，而是面向组织的统一知识基础设施。它把文档、表格、数据库、图片、扫描件、录音和视频治理为模型与智能体可调用、权限隔离、版本可控、证据可追溯的知识，并支持图谱关联、规则推演、实时数值查询以及 REST/MCP/CLI 开放。

## 2. 客户背景与业务故事

集团采购制度散落在文件中，项目关系分布在方案、邮件和会议中，采购金额在业务数据库中，旧制度、别名、OCR/ASR 错误和缺失关系又会影响回答质量。我们围绕“采购制度执行、供应商风险传导与智慧流程中枢项目建设”演示：

```text
建立知识空间 → 多源接入 → 自动加工 → 人工治理 → 统一语义模型
→ 知识图谱 → Semantica 规则推演 → 全文/向量/图谱检索
→ 实时数据库问答 → DeepSeek Harness 多轮问答 → REST/MCP/CLI 开放
```

## 4. 演示前准备

1. 执行 `scripts/demo/preflight_guolian_demo.sh`，必需项全部通过。
2. 检查当前未解决失败任务为 0（历史失败仍保留审计）、在线千问可用、Kimi/内网 Qwen 未进入路由。
3. 逐一打开现行制度、风险图谱、一个数据引用、一个音频时间段和一个视频关键帧。
4. 在 1440×900 窗口完整彩排；再检查 1280×720 无溢出。
5. 清空临时会话，不删除演示空间；保持一份短 Markdown 用于现场上传。
6. 测试环境未恢复时明确使用本机，不宣称远端成功。

## 5. 开场话术

> “今天展示的不是一套只会搜索文件的 RAG 页面。我们从集团真实知识管理链路出发：多源知识先进入统一空间，系统自动解析和治理，业务人员再处理版本、别名和低质量内容；文档形成可引用的原文，关系形成可编辑的图谱，规则形成可证明的新结论，业务数据库提供实时准确数值。最后，员工和智能体通过同一套权限边界调用这些知识。”

## 7. 智能问答固定八轮

1. “《集团本部采购实施细则（2025演示现行版）》主要适用于哪些单位？”
2. “它对供应商准入有哪些要求？”
3. “2026 年演示数据中，各单位采购金额分别是多少，金额最高的是哪家单位？”
4. “按照采购制度规定的统计口径，2026 年 NexusOne 相关有效采购金额是多少？”
5. “东方智造的交付延期会影响哪些项目和责任部门？请说明完整路径。”
6. “项目例会里提到了什么交付风险，视频中展示的哪个建设阶段可能受影响？”
7. “你刚才第二条结论的依据在什么文件、哪一页或什么时间点？”
8. “国联集团明年的实际利润目标是多少？”

验收：历史指代正确；每轮产生真实 Harness Turn/Step；工具按任务选择；结构化问题含 QueryRun；音视频含时间；第 8 轮拒绝编造。

## 8. 技术能力的业务话术

| 技术能力 | 先讲的业务价值 | 必要时补充的技术说明 |

## 9. 客户常见问题与建议回答

| 问题 | 建议回答 |
|---|---|
| 与现有 RAG 有什么区别？ | RAG 是其中的文档检索能力；平台还覆盖治理、版本、本体、图谱、规则推演、实时 DB 查询、权限和服务开放。 |
| 为什么需要图谱？ | 向量找到相似原文，图谱沿已确认关系发现跨文件、多跳对象；两者互补。 |
| 数据库必须先同步吗？ | 实时预览和语义查询不需要；知识索引/快照需要同步，两者会显示不同数据时间。 |
| 如何避免错误 SQL？ | 模型只生成业务 Plan/严格 IR，不能写物理表字段或 SQL；后端按已激活映射确定性编译、参数绑定、只读执行。 |
| 模型能看到数据库密码吗？ | 不能。Secret 由平台加密保存，Harness 和浏览器都拿不到。 |
| 多模态如何接入？ | 扫描件 OCR、录音 ASR、视频音轨+抽帧，均保留页码或时间引用；能力缺失时明确降级。 |
| 自动治理错误怎么办？ | 自动输出形成建议/原始结果，人工确认形成可回滚覆盖层，不静默覆盖人工结论。 |
| 新制度发布后旧版呢？ | 单个文档的版本和历史追溯已支持；本演示中的 2023/2025 材料目前仍是两个独立文档，跨文档制度谱系、条款差异和按生效期自动切换尚未闭环，不能承诺旧版会自动退出默认问答。 |
| 推导结论是大模型生成的吗？ | 不是。正式结论由 Semantica Datalog 基于已发布事实和规则计算，大模型可辅助起草但不能发布结论。 |
| 如何证明结论可信？ | 打开规则、全部前提、来源片段、规则版本和图谱发布版本。 |
| 子企业如何隔离？ | 租户、知识空间、角色/用户授权共同约束检索、片段、会话和工具调用。 |
| 如何对接 Agent 平台？ | REST、MCP 和 CLI；MCP 通过 FastAPI 统一鉴权，不直连底层数据库和索引。 |
| 模型能否在内网？ | 可以通过 OpenAI Compatible 配置，但需先完成连通性、结构化输出和并发验收；当前内网模型不可达所以停用。 |
| 云模型不可用怎么办？ | 已预检备用时由管理员显式切换；其他通道继续真实降级。未实现自动切换时不会声称自动故障转移。 |
| 敏感字段如何保护？ | Schema/策略控制，服务端隐藏或脱敏，浏览器不先接收明文，工具和日志同样受控。 |
| 数据变化是否增量？ | 来源用游标/Hash 识别变化；只处理变化版本/行/Chunk，旧版本保留但不混入当前结果。 |
| 旧文档如何避免进入回答？ | 当前版本和发布版本过滤在检索服务端执行，不依靠模型自行判断。 |
| 人工修改会被自动任务覆盖吗？ | 不会静默覆盖；新的自动结果只形成新建议，可比较并人工决定。 |
| 数据库数值如何审计？ | 数据引用包含数据源、Schema/映射版本、查询时间、对象、行数、SQL 模板和 QueryRun。 |
| 图谱推导关系如何撤回？ | 撤回生成新的有效图谱版本，历史运行和证明保留。 |
| 千问、Kimi、内网模型如何分工？ | 当前在线千问承担核心 LLM 与 Vision；Kimi 当前连接失败且不在路由，不能作为现场备用；内网模型验证后可承接不出域场景，当前停用且不参与路由。 |
| 云模型发送哪些数据？ | 仅发送对应模型任务所需的最小内容；生产需按数据分类、策略和审计决定是否允许出域。 |
| 可以按业务配置模型吗？ | 可以通过模型路由按问答、抽取、治理、结构化规划、视觉、ASR 等场景解耦配置。 |
| 如何继续建设应用？ | 以稳定知识供给版本、能力场景、上线测试门禁和最小权限凭据把底座能力嵌入采购、法务、客服、风险等应用。 |

## 10. 结束话术

> “今天看到的价值不是模型回答得像不像，而是集团知识从接入、治理、语义建模到应用调用形成了同一条可追溯链。原文问题用检索，跨文件关系用图谱，明确规则用推演，实时数值用安全数据库查询；每个环节都受同一权限、版本和审计控制。这样上层每个应用场景不必重复建设自己的知识孤岛。”
