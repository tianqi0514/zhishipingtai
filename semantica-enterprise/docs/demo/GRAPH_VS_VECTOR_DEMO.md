# 图谱检索与向量检索差异演示

> **演示数据，不代表国联集团真实经营数据。** 本演示比较同一问题的真实召回，不得故意削弱任一通道。

## 1. 演示问题

“东方智造发生交付延期后，可能影响集团哪些项目、哪些产品和哪些责任部门？请列出完整关系路径和来源依据。”

每条已登记图谱边都有独立、可核验的 Chunk 证据；同一制度 Chunk 可以支持多条明确陈述，不以“必须来自不同文件”伪造分散性：

| 事实 | 来源 |
|---|---|
| 东方智造供应 NexusOne | 2025 采购细则第四章第十四条，Chunk `document` |
| NexusOne 用于智慧流程中枢项目 | 2025 采购细则第四章第十四条，Chunk `document` |
| 数字科技公司负责智慧流程中枢项目 | RST 建设说明，Chunk `document`；方向统一为责任组织→项目 |
| 东方智造存在交付延期风险 | EML 正文，Chunk `email/body` |
| 数字化管理部协调替代方案 | 例会音频/要点 |
| 风险管理部持续跟踪 | EML/例会音频 |

## 3. 页面操作

1. 选择 `guolian-enterprise-demo`。
2. 在“知识服务 → 检索调试”输入固定问题。
3. 依次切换通道，记录 Query ID、通道计数、前 10 名、各分数、耗时和 Warning。
4. 在图谱结果中展开路径，逐跳打开来源。
5. 在智能问答中启用三路检索，核对最终引用与检索轨迹。
6. 点击回答中的引用编号，定位右侧同一召回项。

## 5. 业务解释

- 全文检索擅长精确名称、文号、原句和编号。
- 向量检索解决“用户不记得原文怎么写”，找到语义相近片段。
- 图谱检索解决“关联对象没有同时出现在同一段证据”，沿供应商→产品→项目，再反向查看“责任组织→负责→项目”的关系发现责任范围。
- 混合检索让图谱负责找关系范围、全文/向量负责提供原始证据，再由 Semantica SearchRanker 的 RRF 融合排序。

图谱不能替代原文证据；向量也不能保证关系路径正确。高质量答案需要两者互补，并保留逐跳 Provenance。

## 6. 失败判定

- 关闭向量却仍显示向量分，或关闭图谱仍展示新路径。
- 图谱路径中的边不存在于当前发布版本。
- 历史制度版本混入当前默认检索。
- 引用无法打开或与召回项不一致。
- 所有通道关闭仍允许提交。
- Reranker 未配置却显示“已重排”。
- 某通道故障导致整体 500，而其他通道本可返回。

当前 `verify_guolian_demo.py` 会调用 keyword、vector、graph、keyword+vector、三路 hybrid 和“请求 rerank”六种模式，并要求真实召回，同时逐条验证 9 条图谱种子事实的来源文档、Chunk 路径和证据词，并拒绝仍在当前图谱中的反向“项目→负责→责任组织”边。最终完整预检 52/52 required 通过，浏览器也已核验排序依据、引用和真实片段。浏览器未逐组穷举六种开关，且三轮完整客户彩排和远端验证仍未完成，不能扩大为最终整套放行。
