# 妙笔 15 分钟上手演示脚本

## 演示目标

用一条清晰路径完成：

**上传材料 → 查看知识加工 → 确认报告输入 → 自动推演与计算 → 生成正文 → 核验依据 → 更新输入并查看影响 → 导出 Word**

本演示使用脱敏客户样本，仅用于功能验证，不代表实时灾情或正式指挥决定。

## 演示步骤

### 1. 上传一份材料（约 2 分钟）

操作：

1. 登录传神智库。
2. 在左侧顶部将当前知识空间切换为“妙笔·客户样本盲测空间”。
3. 进入“知识资产 → 文档资产”。
4. 点击“上传文档”。
5. 解析策略选择“默认策略”。
6. 选择 `需求(1).docx`。如需重新准备完整环境，可一次选择上述 7 份材料。
7. 知识加工方式选择“检索 + 图谱”。
8. 检查页面显示的模型组合：BGE 中文向量、内网 DeepSeek V4 Flash、内网 Qwen3.8 27B FP8 均应为成功状态。
9. 点击“上传”，随后进入“任务”查看真实阶段与进度。

讲解话术：

> 资料进入平台后，不只是保存文件。系统会完成解析、切片、向量索引、实体关系抽取和治理，为后续报告提供可检索、可推演、可追溯的知识基础。

预期结果：

- 首次上传会产生真实解析和知识加工任务。
- 同一文件内容已经存在时显示 `unchanged`，表示 SHA-256 去重生效，不会制造重复版本。
- Word 直接走文本和结构解析，不调用 OCR。

现场建议：不要等待大文件完整加工。可以先展示正在运行的阶段，然后返回文档列表查看已经就绪的 7 份材料。

### 2. 查看输入材料和来源（约 1 分钟）

操作：

1. 在文档列表找到 `临夏州地震应急预案.docx`，点击“查看”。
2. 展示原文预览、文档版本、解析结果和治理信息。
3. 返回列表，再打开 `积石山县6.2级地震应急处置报告推演数据表.xlsx`，说明搜救人员、床位和帐篷数据来自工作表而不是模型猜测。

讲解话术：

> 妙笔后续写作会锁定这批材料形成的知识版本。原文、表格行、计算输入和最终正文之间可以相互追溯，知识更新也不会静默改掉已发布报告。

### 3. 打开妙笔方案任务（约 1 分钟）

操作：

1. 打开 `http://10.5.113.232:9002/miaobi/`。
2. 在顶部“当前方案任务”中选择“积石山县6.2级地震应急处置方案（客户样本盲测）”。
3. 确认左侧只有“方案任务”和“报告编辑”。
4. 查看页面上的三步流程：输入确认、分析计算、报告编辑。
5. 查看知识基线：`妙笔·客户样本盲测知识产品 · V1`，应显示 7 份材料和 587 个知识片段。

讲解话术：

> 用户不需要分别操作规则、公式、算法和写作工作台，只需确认输入、查看系统计算，再编辑报告。专业配置仍在后台，但不打断业务主流程。

### 4. 确认报告输入（约 1 分钟）

操作：

在“输入确认”中重点核对：

| 输入项 | 预期值 |
|---|---:|
| 震级 | 6.2 级 |
| 人口密度 | 305.6 人/km² |
| 搜救人员需求 | 500 人 |
| 可用搜救人员 | 320 人 |
| 创伤床位需求 | 330 张 |
| 县域可用床位 | 110 张 |
| 可调用床位 | 250 张 |
| 帐篷需求 | 7000 顶 |
| 可用帐篷 | 5200 顶 |

然后点击“输入已确认，下一步”。

讲解话术：

> 报告里的权威输入必须先由用户确认。缺失、冲突或未确认的数据不会参加正式计算，也不会被大模型自行补齐。

### 5. 查看推演工具箱并生成报告（约 3—4 分钟）

操作：

1. 在“分析计算”页面查看已有结果：
   - 灾害等级：重大地震灾害（Ⅱ级）；
   - 搜救人员缺口：180 人；
   - 县域创伤床位缺口：220 张；
   - 全域创伤床位缺口：80 张；
   - 帐篷缺口：1800 顶；
   - 采用方案：综合平衡。
2. 点击“重新生成报告”。
3. 观察真实阶段：核验输入、规则推演、确定性计算、知识检索、组织正文、质量检查。
4. 等待系统自动进入“报告编辑”。当前实测完整生成约需 3 分钟。

讲解话术：

> 灾害等级由规则推演形成，资源缺口由确定性公式计算，路线方案来自约束求解；大模型只负责把这些权威结果和知识材料组织成可读正文。这样避免模型自由编造关键数值或正式结论。

预期结果：

- 报告包含 9 个唯一章节，不重复生成章节。
- 搜救、床位、帐篷结果与上表一致。
- 生成失败时不会覆盖当前有效正文。

### 6. 查看正文和引用依据（约 2 分钟）

操作：

1. 在 Plate 编辑器中浏览标题和 9 个章节。
2. 点击正文中的引用编号，右侧切换到“引用依据”。
3. 核对来源文件、正文段落或工作表、原始片段和知识版本。
4. 点击正文中的“测算”或“推演”轻量标记，再查看右侧“计算与推演”。
5. 在一个空段落输入 `/`，确认弹出 Plate 指令菜单；按 `Esc` 关闭即可，不必现场插入复杂组件。

讲解话术：

> 正文保持普通公文阅读体验，技术信息不堆在文章里。每一处引用、测算和推演结论都可以在右侧查看依据，业务人员既能读文章，也能核验它为什么这样写。

### 7. 演示一个输入变化（约 2 分钟，推荐保留）

操作：

1. 返回“方案任务 → 输入确认”。
2. 在“可用搜救人员”一行点击“修正”。
3. 将 320 改为 400，理由填写“演示：新增 80 名可调用搜救人员”。
4. 点击“查看影响”。
5. 核对预览显示：搜救人员缺口 `180 → 100`，并只列出受影响的正文内容。
6. 点击“应用本次变化”。
7. 打开报告，确认关联测算值已经更新为 100，床位和帐篷结果没有变化。
8. 演示结束后按同一流程将 400 恢复为 320，确认缺口恢复为 180。

讲解话术：

> 系统不会因为一个数字变化就重新覆盖整篇报告。它会先计算影响范围，用户点击应用后，只更新依赖该输入的测算和正文块，并保留前后版本。

### 8. 简单修改并导出 Word（约 2 分钟）

操作：

1. 在正文中选中一小段叙述文字，右键选择“改写”或“缩写”。
2. 等待 Agent 生成修订建议。
3. 核对建议没有改变可信数值和推演结论后，点击接受；如不满意可拒绝。
4. 在右侧切换到“审校问题”。
5. 点击“执行生产质量检查”。如出现人工确认项，逐项核对后点击“确认”，再重新检查。
6. 页面显示“审校通过”后，点击“正式 Word”。
7. 在下方导出记录点击“下载”，打开 DOCX。
8. 检查标题、九章正文、表格、引用编号、页码和中文字体。
9. 如需向客户解释依据，可再点击“依据报告”，下载独立的推演依据 Word。

讲解话术：

> 非推演类文字可以由 Agent 辅助扩写、改写和缩写，但修改先以建议形式出现。正式导出前，系统会检查章节、重复内容、权威数值、规则结论、引用和人工确认，只有通过后才能形成 Word。

## 结束总结（30 秒）

> 这条流程证明妙笔不是套模板填文字：上游材料先进入知识底座，中间由用户确认事实、规则和公式产生可核验结果，Agent 再生成可编辑正文；数据变化时系统能定位影响，最后输出正式 Word 和独立依据报告。文章写作、业务计算与知识溯源由同一条版本链连接起来。

## 常见情况

- **重复上传显示 unchanged**：这是内容去重成功，可以直接说明系统不会重复加工相同文件。
- **首次加工耗时较长**：现场只展示任务阶段，使用提前完成的知识版本继续演示；不要用假进度代替。
- **报告生成需要约 3 分钟**：等待期间讲解“规则结论、确定性计算、知识引用和 Agent 叙述”的职责边界。
- **出现旧六菜单页面**：强制刷新浏览器，确认加载当前版本。
- **质量检查未通过**：按右侧问题修正文稿或确认业务节点，不要绕过检查直接导出。
- **Word 按钮不可用**：先完成生产质量检查和待确认项。
