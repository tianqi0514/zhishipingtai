# 妙笔 15 分钟上手演示脚本

## 演示目标

用一条业务路径完成：

**上传业务材料 → 形成知识 → 选择本报告材料 → 确认输入 → 推演计算 → 生成与修改正文 → 核验依据 → 导出 Word**

本演示使用脱敏样本，只验证平台能力，不代表实时灾情或正式指挥决定。

## 演示材料

用户只需要准备四份日常业务材料：

1. `临夏州地震应急预案.docx`：提供分级、职责和处置依据；
2. `需求(1).docx`：提供本次方案目标和交付要求；
3. `应急救援保障方案生成智能体项目技术要求-0908-1.docx`：提供项目要求；
4. `积石山县6.2级地震应急处置报告推演数据表.xlsx`：提供震级、人员、床位和物资输入。

不要上传本体 YAML、报告 Spec YAML 或 Chunk YAML：

- 语义模型由智库从业务材料中生成候选，再由业务人员确认；
- 报告规范已经内置在妙笔的场景配置中，并支持查看、修改和版本化；
- Chunk 是系统内部解析和引用定位结果，不是用户材料。

现场建议提前完成这四份材料的首次加工，演示时上传其中一份或展示相同内容的去重结果。

## 0. 演示前检查（不计时）

- 传神智库：`http://10.5.113.232:9002/`
- 妙笔：`http://10.5.113.232:9002/miaobi/`
- 选择已经准备好的演示知识空间。
- 确认四份材料均为“就绪”，模型和必需服务状态真实可用。
- 确认方案任务已绑定可用知识产品 Release。

## 1. 上传业务材料（2 分钟）

操作：

1. 登录传神智库并选择演示知识空间。
2. 进入“知识资产 → 文档资产”，点击“上传文档”。
3. 选择一份 DOCX 或上述 XLSX，确认加工方式和实际模型组合。
4. 点击上传，进入任务中心查看真实阶段和进度。
5. 打开已就绪文档，展示原文、版本、表格位置和治理画像。

话术：

> 用户上传的都是业务中原本就存在的资料。智库在后台完成解析、切片、检索索引、实体关系抽取和治理；Word 不会错误调用 OCR，扫描件才会按策略识别。

预期：首次上传真实加工；相同内容显示 unchanged，不产生重复版本。

## 2. 展示知识如何形成（1.5 分钟）

操作：

1. 进入“知识治理 → 知识结构”。
2. 打开当前语义模型的“候选治理”。
3. 点击“从当前知识重新生成”，查看由真实对象和关系形成的候选及依据。
4. 打开一项依据；演示接受/修正，但现场可以不发布新版本。

话术：

> 语义模型不是要求业务人员先写一份 YAML 再上传。系统从已经发布的知识中提出对象和关系候选，业务人员只负责确认名称、别名和含义，发布后形成可追溯版本。

## 3. 创建任务并选择本报告材料（1.5 分钟）

操作：

1. 打开妙笔，新建或选择“积石山县 6.2 级地震应急处置方案”。
2. 在“本报告使用材料”中点击“选择材料”。
3. 从当前知识产品 Release 中选择上述四份业务材料，分别设置“事实来源”“法规依据”等用途。
4. 展示每项材料的固定版本和加工状态。
5. 如需补充材料，点击“去智库上传材料”；上传完成后返回妙笔刷新候选。

话术：

> 知识产品决定应用可以使用的知识范围，本报告再从中选择真正相关的材料并锁定版本。后续检索和 Agent 都受这个范围约束，不能引用没有选入任务的文件。

## 4. 查看内置场景配置（1 分钟）

操作：

1. 点击右上角“场景配置”。
2. 快速展示四类真实配置：输入项、报告章节、推演工具箱、输出与确认。
3. 指出章节可设为 Agent 撰写、工具箱填充或混合；测算/推演结果可以选择目标章节。
4. 点击取消，不保存改动。

话术：

> 这是某一类应急报告特有的规范，所以放在妙笔，不放在通用智库。每个选项都会改变运行：输入决定校验，章节决定生成结构，工具开关决定是否真实计算，结果落点决定写入哪一章，导出格式决定后台允许生成什么文件。

## 5. 确认关键输入（1.5 分钟）

在“输入确认”核对：

| 输入项 | 演示值 |
|---|---:|
| 震级 | 6.2 级 |
| 人口密度 | 305.6 人/km² |
| 搜救人员需求 | 500 人 |
| 可用搜救人员 | 320 人 |
| 创伤床位需求 | 330 张 |
| 县域可用床位 | 110 张 |
| 可调用床位 | 250 张 |
| 帐篷需求 | 7000 顶 |
| 可用帐篷 | 5200 顶 |

打开一项来源后再确认输入，点击“输入已确认，下一步”。

话术：

> 关键输入来自 Excel、文档或数据库，先由责任人核验。场景配置标记为必需且需确认的值如果缺失，系统会真实阻止生成，而不是让模型自行补数。

## 6. 推演计算并生成报告（3 分钟）

操作：

1. 在“分析计算”查看灾害等级和资源缺口。
2. 核验：搜救缺口 180 人、县域床位缺口 220 张、全域床位缺口 80 张、帐篷缺口 1800 顶。
3. 点击“生成报告”，观察核验输入、规则推演、确定性计算、知识检索、章节生成和质量检查等真实阶段。
4. 完成后自动进入“报告编辑”。

话术：

> 推演工具箱负责确定性内容：规则结论由 Semantica 执行，数值由公式计算，方案由真实算法比较。Agent 负责非推演类文字和章节组织，不能自由改写权威数值。

## 7. 编辑正文并核验依据（2 分钟）

操作：

1. 浏览 Plate 正文，正文只显示轻量引用、测算和推演标记。
2. 点击引用，右侧查看文件、版本、页码或工作表片段。
3. 点击测算或推演标记，右侧查看输入、公式、规则和证据链。
4. 在空段落输入 `/`，确认出现完整 Plate 指令菜单。
5. 选中一段普通叙述，右键选择扩写、改写或缩写；结果先作为建议，演示接受或拒绝。
6. 在右侧 Agent 中输入“把处置建议改得更简洁，但保留所有数值和引用”，查看流式建议。

话术：

> 正文保持普通报告阅读体验，技术依据集中在右侧。Agent 修改非权威叙述时先给出建议；测算值和推演结论不能被静默手改。

## 8. 演示输入变化和局部更新（1.5 分钟）

操作：

1. 返回输入确认，将可用搜救人员从 320 修正为 400，填写演示理由。
2. 点击“查看影响”，核验缺口从 180 变为 100，并只列出受影响正文内容。
3. 点击“应用本次变化”，查看关联测算块更新，床位和帐篷不变。

话术：

> 输入变化不会覆盖整篇报告。工具箱先重新计算依赖关系并给出影响预览，只有用户点击应用后才更新对应内容和形成新版本。

演示结束后可用同一流程恢复为 320。

## 9. 审校并导出 Word（1 分钟）

操作：

1. 进入“审校问题”，执行质量检查并处理必需确认。
2. 点击“正式 Word”，等待真实导出任务完成。
3. 下载并打开 DOCX，检查标题、章节、表格、引用、页码和中文字体。

话术：

> 导出前会核验章节、引用、权威数值、推演结论和人工确认。正式 Word 来自当前不可变文稿版本，并保留对应知识、配置、规则和计算版本。

## 结束总结

> 传神智库解决材料如何变成可信知识，妙笔解决某类报告如何使用这些知识。业务人员上传真实资料、确认关键输入；推演工具箱负责结论和数字；Agent 负责叙述；Plate 负责编辑；右侧依据和版本链负责核验。由此形成从材料到正式 Word 的闭环。
