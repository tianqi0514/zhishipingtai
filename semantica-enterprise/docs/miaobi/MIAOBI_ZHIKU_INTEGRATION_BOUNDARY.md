# 妙笔与传神智库的产品边界

## 一句话原则

传神智库负责把组织材料变成可检索、可计算、可推演、可追溯的知识；妙笔负责在一个具体写作场景中选择这些知识、确认输入、运行工具并形成报告。

用户不需要上传本体 YAML、切片 YAML 或报告 Spec YAML。它们分别被“知识结构候选”“系统内部切片”和“妙笔场景配置”取代。

## 用户实际上传什么

用户只上传业务中原本就存在的材料，例如：

- 政策、制度、预案和技术要求；
- 灾情简报、项目材料和工作记录；
- Excel 事实表和数据库数据；
- 扫描件、图片、地图及附件。

以下内容不是普通用户的上传材料：

- 语义模型或本体文件：由智库根据已发布知识生成候选，业务人员确认和修正后发布版本；
- Chunk 文件：由解析和切片策略自动形成，仅在技术诊断和证据定位中使用；
- 报告生成规范：内置在妙笔场景中，由管理员通过业务化配置查看、修改和发布新版本；
- 公式、规则和工具定义：由场景配置引用受控版本，普通写作者不需要逐项配置。

## 职责划分

| 能力 | 传神智库 | 妙笔 | 用户能看到什么 |
|---|---|---|---|
| 文件上传与版本 | 权威实现 | 选择任务材料 | 材料名称、固定版本、加工状态 |
| 解析、OCR、表格理解 | 权威实现 | 读取加工结果 | 原文、页码、工作表和证据 |
| 切片与索引 | 权威实现 | 按任务材料范围检索 | 引用和来源，不暴露工程文件 |
| 实体、关系与图谱 | 抽取、治理、发布 | 用于写作检索和推演 | 业务对象、关系和证据链 |
| 语义模型 | 生成候选、人工确认、版本发布 | 使用已发布版本 | 候选依据、业务名称、版本 |
| 数据库语义查询 | Schema、映射、只读查询 | 调用查询结果写作 | 实时结果、数据时间和引用 |
| 场景输入 | 提供来源事实 | 定义本场景必需输入并确认 | 哪些值必须确认、来自哪里 |
| 章节规范 | 不负责 | 内置、可编辑、不可变版本 | 章节目的、生成方式、引用要求 |
| 推演与计算 | Semantica 和确定性服务 | 选择本场景启用的工具 | 输入、公式/规则、结果、影响 |
| 正文生成 | 提供知识工具 | Agent 生成并交给 Plate 编辑 | 普通正文和轻量引用标记 |
| 修改与导出 | 提供来源追溯 | 建议、版本、审校、Word/PDF | 可接受/拒绝的修改和正式文件 |

## 端到端业务流程

1. 在传神智库创建知识空间并上传业务材料。
2. 系统完成解析、切片、索引、语义抽取和治理。
3. 在“知识结构”中根据真实对象和关系生成候选，业务人员确认后发布语义模型版本。
4. 在妙笔创建方案任务，绑定不可变的知识产品 Release。
5. 从 Release 中选择本报告实际使用的材料；选择时固定文档版本。
6. 妙笔依据场景配置列出必需输入，用户核验来源并确认。
7. 推演工具箱运行受控规则、公式和算法，输出结构化结果及影响范围。
8. Agent 只生成非权威叙述和章节组织；权威数值、结论及引用由服务端插入。
9. Plate 展示可编辑正文；右侧展示每个章节使用的知识、计算和推演依据。
10. 输入改变时先预览影响，用户点击应用后才局部更新关联内容并形成新版本。
11. 审校通过后导出 Word、PDF 或场景允许的其他格式。

## 场景配置及其真实作用

| 配置项 | 业务意义 | 实际运行影响 |
|---|---|---|
| 输入项 | 报告成立前必须掌握的事实 | 决定输入确认清单、类型/范围校验和生成阻断 |
| 是否需要确认 | 哪些输入必须由责任人核验 | 未确认时阻止或警告，取决于缺失数据策略 |
| 章节 | 正式报告需要哪些内容 | 决定 Agent 生成协议和最终 Plate 章节结构 |
| 章节生成方式 | Agent 撰写、工具箱填充或两者组合 | 决定该章节是否请求模型、是否插入权威结果 |
| 章节引用要求 | 本章节能否缺少来源 | 进入生成后的质量门禁 |
| 推演开关 | 是否需要规则推导结论 | 控制真实 Semantica 运行，不启用就不生成推演块 |
| 计算开关 | 是否需要确定性数值 | 控制公式运行，不启用就不生成测算块 |
| 方案比较开关 | 是否生成备选方案 | 控制算法运行和方案块 |
| 结果落点 | 某个结果应出现在哪一章 | 决定可信业务块插入的目标章节 |
| 允许人工覆盖 | 是否允许业务人员改写权威输入 | 关闭后前后端都拒绝覆盖；开启后必须记录理由 |
| 缺失/未核验策略 | 数据不足时应阻断还是警告 | 直接控制报告生成接口是否继续 |
| 标题规则 | 正式文稿的默认命名 | 创建报告时真实生成标题 |
| 允许导出格式 | 场景交付物类型 | 控制导出按钮与后端格式校验 |
| 决策确认点 | 哪些关键结论必须人工决定 | 决定审校和发布前的确认门禁 |

每次保存场景配置都会形成新的不可变版本。已有任务继续使用创建时锁定的版本，避免管理员修改配置后静默改变正在编写的报告；新任务使用新版本。

## 明确不提供的无效配置

- 不允许普通用户上传或编辑原始 Chunk YAML。
- 不允许把整份系统提示词作为“报告规范”配置。
- 不允许选择一个未接入运行链路的模型、公式或按钮。
- 不允许让模型直接修改权威数值或 Semantica 正式结论。
- 不允许后台更新材料后静默覆盖已经确认的正文。
- 不设置与报告结果无关的装饰性参数。

## 需要继续保留的专业入口

命名空间、模型路由、规则版本、公式版本和技术诊断仍然存在，但放在管理员或技术信息区域。普通写作者只面对材料、输入、计算结果、正文、依据和导出。
