## 发现与修复

- “仅向量化”资料不能被当作图谱依据：保留真实空依据提示，图谱正向验收改用“两种方式”。
- 固定知识产品版本原先可能间接读取可变事实：图谱发布增加带校验值的不可变依据快照；旧版本缺少快照时明确阻止替代读取。
- Agent超时后任务仍停在执行中：失败/取消事件同步报告状态，已有失败任务可重新开始；空草稿不再显示“报告已生成”。
- 普通段落不跟随输入失效：增加段落依赖、影响预览、待核对及明确人工核对入口；不静默改写人工正文。
- 普通段落已失效却可通过发布接口绕过检查：将待更新段落纳入正式发布阻断条件。
- 切回原文模式遗留旧规则、零结果不能确认：清除旧规则选择，允许确认真实空结果并使旧结论失效；不把空结果解释为没有风险。
- 生成与输入/正文并发变更：版本检查失败时保留当前正文，要求重新生成。
- 内部写作凭据范围不足：拒绝访问完整报告上下文；原单元测试手工构造的凭据遗漏space_ids，按真实签发结构补齐，并新增缺失/空范围必须403的断言，未放宽权限检查。
- 右键缩写被“车辆数量”误判为实时查询：FastAPI只为纯文字修订签发单轮动作类型，DSH仍必须加载项目上下文，但不再强制无关SQL；核验事实、补充依据、普通问答和正式报告保持原证据工具要求。失败修订同步为失败状态。
- 编辑工具补调后丢失编辑目的、输出调用摘要：插件补调提示保留局部修订任务，不再转成普通问答。阻止新增引用及编写指令。真实浏览器缩写将57字改为40字，保留保障组D、核实库存运输、协调送水、车辆及到达时间待现场确认；2个Step、1次工具、8个流式增量，点击应用后保存成功。
- Word模板自动添加固定文种和平台开场白、依据报告没有新章节证明链：去掉自动附加话术，依据报告逐条列出实际结论、全部前提及各自来源；按正文绑定去重统计规则结论，不以历史预览次数冒充结论数量。
- 最后逐条阅读导出文件发现：多次生成的历史绑定复用了引用编号，依据报告可能把当前编号映射到旧来源。改为先按所导出文稿版本的真实块ID筛选绑定，再生成引用和计算清单；新增同编号、不同历史块的回归，以及浏览器下载后的逐条来源比对。没有删除历史绑定或文稿版本。
- 首轮正文混入“该缺口应列入资源保障章节”：增加编写说明过滤与生成约束，需重新生成，不能靠改测试断言接受。
- 浏览器导出测试曾误点旧记录：改为等待该次真实导出响应并按导出ID定位下载，增加DOCX/PDF文件头校验。旧下载不能作为版式通过证据。
- 资源争用时曾有Plate组件测试超过默认5秒：不提高断言超时，单独重测全部20项通过。

浏览器第一轮11组点击检查通过，Console/pageerror为0。DOCX/PDF按真实导出ID下载并验证文件头；分别用LibreOffice和Poppler渲染，正式报告均为1页，已检查中文、标题、引用、数字和页脚。错误下载测试产生的旧渲染文件单独隔离，不纳入验收。最终镜像及收尾复测记录在下方追加。

## 验收边界

- 本轮本机运行；未据此宣称内网服务器已更新或重新通过生产验收。
- 一次模型成功不构成可用率保障。观测到一次Runtime配置请求超时，失败被保留；后续真实默认模型最小请求约1.9秒，重试Agent成功。
- 生成正文仍有措辞重复和编写约束被引用的可能，需要业务人员使用编辑/助手修订；规则证据正确不等于整篇文章自动达到正式签发质量。结构审校通过不是业务验收背书。
- 完整Plate包生产构建存在大分包及浏览器兼容模块告警。本轮没有删插件或调高告警阈值，未做弱网首屏专项优化。
- 依据准备最多1500条事实、四跳有界关系扩展；单次推演及展示有数量上限，截断明确提示。不是无限大图谱分析或大规模性能验收。
- 不新增一套本体/规则后台，不让用户上传报告规范或本体YAML。应用按章节选择智库中已发布的对象、关系和规则；本体自动建议的质量仍须业务确认。
- 未配置关系要求的章节继续普通材料检索写作；关系不存在只表示证据缺失，不表示现实中没有风险。
- 未重新完成所有Plate插件、多用户协作压测、全部灾种、外部GIS及其他历史P4验收，因此不打生产候选Tag。
