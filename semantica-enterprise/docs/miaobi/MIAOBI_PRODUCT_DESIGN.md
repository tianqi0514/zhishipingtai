# 妙笔产品设计

## 产品目标

妙笔把已发布的组织知识、实时数据、业务规则和确定性算法转化为可编辑、可核验、可更新的专业文稿。用户看到的是“准备资料—确认事实—计算与推演—比较方案—写作—审校发布”的连续业务过程，不需要理解 Datalog、Query IR 或模型工具协议。

## 应用信息架构

| 页面 | 用户要完成的事 | 核心对象 | 完成后的下一步 |
|---|---|---|---|
| 工作台 | 看清项目状态、待办和风险 | WritingProject、DecisionGate | 打开当前最紧急任务 |
| 方案任务 | 新建任务、选择场景与知识版本、上传材料 | ScenarioPackageVersion、KnowledgeProductRelease | 进入事实确认 |
| 数据与事实 | 核对已知、缺失、冲突和低置信度事实 | ProjectFact、FactConflict | 执行计算与规则推演 |
| 推演工作台 | 查看判据、计算、规则证据和备选方案 | ComputationRun、InferenceRun、AlternativePlan | 选择方案并生成文稿 |
| 妙笔文稿 | 编辑、引用、评论、修订、协同 | WritingDocument、Plate Value、WritingBlockBinding | 执行审校 |
| 审校发布 | 处理错误、确认闸门、导出和发布 | ReviewIssue、DecisionRecord、ExportJob | 形成不可变正式版本 |

配置能力集中在配置中心：场景包、文稿模板、规则集、公式库、算法与 MCP、模型路由、输出模板、审校规则、方案策略和权限。

## 地震主流程

1. 知识管理员发布“应急保障知识产品”的稳定 Release。
2. 业务人员创建“积石山县 6.2 级地震应急处置方案”任务，绑定地震场景包和知识 Release。
3. 系统解析简报、预案、表格、扫描件、地图与数据库，形成分类型事实。
4. 用户处理缺失值、口径冲突和低置信度内容。
5. 判据服务执行数值边界，Semantica 使用判据事实和组织关系推导灾害等级、任务与影响关系。
6. 公式引擎计算需求与缺口，结构化查询读取实时库存，算法服务生成速度、安全、综合三套方案。
7. 用户选择方案，Plate 根据章节目标组织草稿；权威事实以可信业务块写入。
8. 用户编辑普通叙述；测算值和推导结论只能通过重新计算、重新推演或带理由人工覆盖更新。
9. 审校检查缺引用、失效来源、冲突、未确认闸门和版式。
10. 发布不可变文稿版本，服务端生成 DOCX、PDF、JSON、XLSX 和存在路线时的 GeoJSON。

## 事实可信等级

| 类型 | 是否可直接写入正式结论 | 约束 |
|---|---|---|
| 官方简报已知、预案原文 | 可以 | 必须绑定文档版本和位置 |
| 实时数据库 | 可以 | 必须绑定成功 QueryRun 和数据时间 |
| 确定性测算 | 可以 | 必须绑定公式版本和输入快照 |
| Semantica 推导 | 可以 | 必须绑定规则版本、前提和证据链 |
| MCP 返回 | 视工具而定 | 必须绑定工具版本、请求摘要和时间 |
| 模型抽取 | 不直接作为正式决定 | 需置信度与人工或规则校验 |
| 人工补齐、人工覆盖 | 可以 | 必须记录操作者、理由和影响范围 |
| 历史失效 | 不能进入当前正式版本 | 历史文稿仍按原 Release 可追溯 |

## Plate 交互约束

- 普通段落允许自由编辑。
- `computed_metric`、`inference_conclusion` 默认只读；修改入口分别是“调整输入并重算”和“调整事实或规则并重推”。
- 人工覆盖会生成新事实和 `manual_override` 状态，不会擦除原自动值。
- AI 修改以 Suggestion 展示，用户接受后才进入正文。
- 来源变化只标记依赖块 `stale`，不自动重写整篇文稿。
- 左栏显示目录与缺失项，中栏编辑，右栏显示助手、依据、计算推演和审校问题。

## 发布门槛

以下任一条件成立时禁止正式发布：关键事实缺失、未解决的高风险冲突、失效业务块、权威结论缺来源、必需 DecisionGate 未确认、导出模板不匹配、用户无发布权限。预览导出可以生成，但必须带“草稿”状态，不能冒充正式版本。
