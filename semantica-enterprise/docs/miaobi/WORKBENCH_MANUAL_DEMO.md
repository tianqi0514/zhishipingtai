# 妙笔写作工作台手工演示

## 目标

用一个项目创建两篇文章，证明资料可复用但文章范围独立，并完成从上传到 Word 的闭环。

## 操作

1. 打开 `/miaobi/`，新建“地震应急材料演示”项目；可选择已有知识空间，也可先空白创建。
2. 新建“应急预案修订稿”，读者填“管理部门”，用途填“修订长期制度”。创建后直接进入 Plate，输入 `/` 检查命令菜单。
3. 返回项目，在“准备资料”上传灾情简报、应急预案和资源台账；上传样稿时将用途改为“样稿与格式”。文件由知识底座真实解析并固定版本。
4. 若项目最初为空白，点击“添加资料来源”，选择已完成知识加工的空间，再上传材料。
5. 新建第二篇“本次事件处置方案”，只勾选本次简报、资源台账和制度依据为“用于本文”，取消样稿的事实性材料范围。
6. 确认会影响结论的震级、人口密度、资源需求和可用量；普通名词不逐项确认。
7. 进入“起草编辑”。缺项时点击“生成可写章节”，系统只生成已经具备条件的章节；补齐材料后可继续生成。
8. 在编辑器右侧检索并插入依据，点击引用编号查看真实文件、版本、页码或结构位置。
9. 选中一段正文右键执行扩写、缩写或改写；结果先成为建议，分别演示接受和拒绝。
10. 在右侧助手输入“请把第二章改得更适合管理层审阅，并保留数字和引用”，查看真实 Agent 事件后插入为修订建议。
11. 演示共同依据更新：把可用搜救人员从 320 改为 400，先预览缺口 180→100 及受影响正文、摘要和表格；应用前正文不变，应用后统一更新并形成新版本。
12. 进入“检查导出”，解决阻塞问题，导出 DOCX 和 PDF。实际打开文件检查中文、目录、分页、表格、图片和正文一致性。

## 预期结果

两篇文章在同一项目内独立存在；未用于本文的材料不会进入检索和 Agent；样稿不成为事实；公式和 Semantica 结论可追溯；历史版本保留 180，当前版本为 100；Word 能用于业务讨论而不是网页截图。
