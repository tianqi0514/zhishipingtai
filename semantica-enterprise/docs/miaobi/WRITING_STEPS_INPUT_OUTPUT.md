# 妙笔七步写作输入输出

妙笔在业务上分七步，界面只显示“准备资料、起草编辑、检查导出”三个阶段。七步不是七个强制向导页；用户可以先建空白文章、先写已经具备依据的章节，再补充资料。

## 1. 明确写作任务

输入：文章类型、名称、目标读者、写作目的、地区/组织/事项/时间范围、可选样稿和写作要求。

处理：建立文章级写作契约，给出初始目录和资料建议，判断是否可能需要检索、计算或规则推演。

输出：项目内独立文章、空白 Plate 文稿、资料建议。文章创建不以知识空间、规则或计算是否就绪为前置条件。

## 2. 准备资料

输入：妙笔内上传文件、智库中已有资料、数据库查询结果、补充说明和样稿。

处理：智库负责解析、切片、索引、版本与权限；妙笔保存本次文章采用的固定资料版本。资料用途与可信状态分开：用途包括本次业务资料、制度依据、参考资料、样稿格式；状态包括当前有效、历史版本、待核验和失效。

输出：可预览资料、解析状态、来源定位、异常与缺口。样稿只能影响结构和表达，不能自动成为业务事实。

## 3. 确认信息与目录

输入：解析结果、文章类型、模板建议和用户补充。

处理：只整理会影响本文的关键事实、冲突、低置信度内容与缺失项；每章建立“写什么、依据什么、需要确认什么、是否需要工具”的计划。

输出：本文采用的事实和口径、可编辑目录、章节准备状态。未就绪状态必须精确到章节，不得无差别阻止整篇写作。

## 4. 按需分析计算

输入：已确认事实、单位、时间口径、规则/公式/算法版本和目标约束。

处理：原文整理使用检索；数字使用确定性公式或数据库查询；关系结论使用 Semantica；路线和资源优化使用真实算法。普通文章没有计算需求时直接跳过。

输出：带输入、方法、版本、来源、适用条件和目标章节的结果。行政决定类结果保持“建议/待确认”，不得由模型冒充正式决定。

## 5. 生成初稿

输入：目录、章节要求、固定资料版本、已确认事实、已采用工具结果和文风要求。

处理：DSH Agent 按章节检索和生成；权威数值只能引用受控结果；重要表述建立正文块到来源/事实/结果的绑定。

输出：可编辑 Plate 初稿、段落依据、待补充标记和失败章节。按章失败只重试该章，不覆盖已经人工修改的正文。

## 6. 修改与审校

输入：人工编辑、右键扩写/缩写/改写、对话指令、新资料和输入变化。

处理：表达修改形成可接受建议；事实或依据修改先做影响预览，再重算和生成受影响段落建议。审校覆盖结构完整性、事实一致性、引用有效性和版式。

输出：可接受/拒绝的修改建议、审校问题、新文稿版本及更新后的绑定。自动计算不等于自动覆盖正文。

## 7. 定稿与导出

输入：确认后的正文、来源、计算/推演结果和输出模板。

处理：区分草稿导出、确认定稿和业务签发；冻结正文、模板、资料、事实、规则、计算、引用和审校快照。

输出：可打开的 DOCX/PDF、不可变定稿版本和后台依据记录。系统不能把下载文件等同于获得正式签发授权。

## 关键返回路径

- 新资料到达：回到第 2 步，仅重新检查受影响章节。
- 事实冲突：回到第 3 步，保留原值和处理理由。
- 输入数值变化：回到第 4 步，预览影响后局部重算。
- 文章表达不合适：停留第 6 步，不重跑无关计算。
- 已定稿内容受影响：保留原定稿，创建修订草稿。
