# 写作图谱产品设计

## 1. 产品目标

写作图谱把真实材料转换为可治理、可发布、可被妙笔使用的写作知识。它不是现有知识图谱的换色视图，也不是把模型抽取结果直接当成事实。

完整业务链路如下：

```text
文档版本
  -> ContentElement / Chunk
  -> Evidence
  -> Entity / Claim 候选
  -> Fact 候选与 Relation 候选
  -> 人工治理
  -> WritingGraphRelease
  -> 妙笔章节检索与正文 Chunk 绑定
  -> 事实变更影响预览
  -> 用户选择应用
  -> 新文章版本
```

## 2. 五层模型

五层不是五次串行模型调用，而是五类职责不同的知识对象。

| 层 | 业务含义 | 产生方式 | 能否直接用于正式稿 |
|---|---|---|---|
| Evidence | 原文件中可定位、不可变的来源片段 | 平台按解析结果确定性生成 | 作为来源使用 |
| Entity | 稳定业务对象 | 模型提及候选 + 程序归一 + 人工确认 | 已确认对象可以使用 |
| Claim | 某份材料声称了什么 | 模型联合抽取，必须引用 Evidence | 不能等同于事实 |
| Fact | 平台在指定范围和时间内采用的事实 | Claim 校验 + 人工确认或确定性计算 | 仅 verified 且当前有效时可使用 |
| Relation | 关系型 Fact 的图谱投影 | 服务端从已确认关系事实确定性投影 | 仅随对应 Fact 生效 |

核心不变量：

- Evidence 不由模型创作，必须落到真实文档版本、ContentElement 或 Chunk。
- Claim 必须至少引用一个当前用户可访问的 Evidence。
- Fact 必须来自 Claim、确定性计算或受控结构化查询；模型不能将自身输出标记为 verified。
- Relation 不是独立事实源，必须反向关联 Fact、Claim 和 Evidence。
- 历史对象不物理删除，通过版本和有效状态保留追溯。

## 3. 四路加工

一次解析产生的 ContentElement 和 Chunk 可以选择以下一个或多个目标：

1. 全文索引：只向 OpenSearch 发布文本索引。
2. 向量索引：只生成向量并向 Qdrant 发布。
3. 知识图谱：沿用现有实体、关系和事件抽取及 FalkorDB 发布。
4. 写作图谱：生成五层候选，进入人工治理和独立发布流程。

四路具备独立状态。一路失败不撤销其他已成功结果。旧的 `vector`、`graph`、`both` 参数继续兼容，由服务端映射为明确目标集合。

## 4. 写作知识治理

现有治理工作台增加“写作知识”分类，不建立重复后台。普通用户处理：

- 实体名称、类型和别名；
- Claim 的主体、谓词、客体、时间和适用范围；
- Fact 的值、单位、有效期和当前状态；
- Relation 的两端实体和谓词；
- Evidence 的定位完整性和来源版本；
- 同一指标、同一对象或同一时点的冲突。

治理操作为接受、修改后接受、拒绝、合并、拆分、设为当前、设为历史。每次操作保存原值、新值、理由、操作人、时间和受影响对象。后续自动抽取只能产生新候选，不能覆盖人工确认结果。

## 5. 发布模型

`WritingGraphRelease` 是不可变快照，包含：

- 已确认 Entity、Fact、Relation；
- 它们引用的 Claim 和 Evidence；
- 发布时的文档版本和内容哈希；
- 发布人、发布时间、版本号和 Checksum。

妙笔文章选择一个发布版本后，所有章节生成、引用验证和影响传播都以该快照为边界。新发布不会静默改变既有文章。

## 6. 妙笔使用方式

一个项目可包含多篇文章。项目共享材料和事实，文章独立固定：

- 写作图谱发布版本；
- 文章类型、受众、目的、地区、组织、事项和时间范围；
- 采用材料版本；
- 目录、正文 Chunk、绑定和文章版本。

文章字段不是提示词装饰：它们参与事实适用范围过滤、目录规划、关系查询、章节生成和审校。

按章生成时，DSH 先读取写作任务，再查询已确认 Fact、Evidence、Relation 和必要的公开标准；精确数字只使用 verified Fact、结构化 QueryRun 或 ComputationRun。正文中的分析性衔接允许模型生成，但标记为 narrative，不能伪装成已确认事实。

## 7. 事实变更联动

依赖图为：

```text
Evidence -> Claim -> Fact -> ComputationRun / Derived Fact
                              -> WritingChunkBinding -> ArticleVersion
```

修改权威值只生成候选版本。系统重算确定性计算并生成 `ImpactPreview`：

- 确定影响：由显式 ID 依赖可完整遍历；
- 疑似影响：只有语义相似，没有显式绑定；
- 无影响：不在依赖闭包内。

用户可以全选或逐项应用。应用前正文不变；未选择的块保持原文并标记 stale；人工覆盖和定稿版本不得被静默修改。

## 8. 用户界面

智库侧：

- 上传/重新加工时选择四路目标；
- 治理工作台处理写作知识候选；
- 图谱页切换“知识图谱 / 写作图谱”；
- 写作图谱提供业务关系视图和事实依据视图。

妙笔侧：

- 创建项目和多篇文章；
- 选择知识空间与已发布写作图谱版本；
- 生成和编辑目录；
- 使用 Plate 按章生成、编辑和审校；
- 右侧查看段落依据、计算与影响、Agent 助手和审校问题；
- 修改事实时先查看影响，再选择应用；
- 导出 DOCX/PDF。

## 9. 非目标

- 不让模型直接发布 Fact。
- 不把写作图谱默认混入现有问答排序。
- 不用字符串搜索替换实现联动。
- 不因一个字段缺失阻断无关章节。
- 不把样稿内容作为本次业务事实。
- 不依赖 `chuanshenmiaobi` 的 API、SQLite 或 8100/8101 服务。
