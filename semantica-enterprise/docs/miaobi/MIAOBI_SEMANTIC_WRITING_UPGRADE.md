# 妙笔：面向章节的知识约束写作

基线：9189687；分支：codex/miaobi-semantic-writing。本文为本轮实现与验收契约，完成状态以测试记录为准。

## 用户流程

1. 选择业务材料，查看真实待确认输入；没有材料时只提示添加材料。
2. 根据场景的章节要求准备知识依据：原文、业务对象及关系、规则结论、缺失项。
3. 查看实际命中的关系和推演结果，确认应用本次依据；不自动发布组织图谱。
4. Agent 根据已应用的章节依据写正文，Plate 保持完整编辑功能；正文只用轻量引用。
5. 点击段落或引用，在右侧查看来源、规则前提、公式输入和版本。
6. 新知识版本或输入变化后预览影响；用户应用后受影响正文标为需要更新，手写内容不被静默覆盖。

## 分工

- 智库继续负责材料解析、知识治理、本体版本、关系和知识产品发布。
- 妙笔配置章节的业务问题、涉及的对象类型、必需关系、允许规则和写作要求。
- 本体版本负责统一关系别名与对象类型；仅发布版本可被绑定，歧义不得自动合并。
- Semantica 继续执行 Datalog；平台做有界关系遍历、权限过滤、证据装配和章节依赖记录。
- 公式负责数值，Agent 负责叙述。无关系记录只表示未检索到，不代表现实中不存在。

## 版本与权限边界

新增图谱发布时保留有效事实及来源快照，包含属性事实，避免历史报告从可变 Fact 表读取后来改写的关系。旧图谱缺少快照时明确提示重新发布，不能用当前数据冒充旧版本。

章节依据运行保存知识产品版本、图谱版本、本体版本、规则版本、事实快照、推演证明、章节引用及校验摘要。预览与应用分离；确认依据时检查材料、场景及前一依据版本。生成正文和应用输入变更还会检查文稿版本，避免覆盖并发编辑。源文件访问重新检查租户、知识空间、材料和版本范围；内部Agent凭据必须覆盖报告知识范围，图谱工具进一步遵守本次请求的空间范围。

## 本轮验收

- 空任务、只含文本任务、已具备图谱任务显示一致的准备状态。
- 有源文件的安置点—供水设施—停供状态—责任部门场景：真实 Semantica 推导风险，多跳关系进入指定章节。
- 停供变恢复后新知识版本不再支持原风险结论，预览指出失效依据和精确受影响段落；历史文稿与旧依据保持可追溯。
- 未选材料、跨空间事实、未发布本体/规则、未知引用拒绝进入正文。
- 500−320=180，320→400 后缺口100；段落引用依赖也被标记，无关段落不动。
- 真实 DSH 写作、Plate 点击引用、Word导出、现有自动化回归。

以上列出验收目标；真实接口、浏览器与仅合约层的完成情况分别记入测试报告。当前停供变恢复的再推演通过真实Semantica算法合约测试，未据此宣称已完成外部业务数据库持续更新验收。

## 页面减法

保留任务准备和报告编辑两项导航。推演依据在任务步骤中查看。右栏以助手、依据、检查为主要入口；算法名、内部ID和执行日志按需展开。场景配置只展示实际生效的字段，规则/本体来自智库已发布记录。

## 现在如何试用（约5分钟）

1. 打开本机 `/miaobi/`，选择“安置点供水保障报告”验收任务。
2. 在“方案任务”的“输入确认”查看三份材料和人员输入。材料解析及图谱发布仍在智库，任务只引用这些固定版本。
3. 点击“分析计算”，展开“章节依据”。看“安置点A依赖供水站C”“供水站C发生供水中断”如何成为有两条来源的规则结论，以及第三份材料中的保障组D职责。
4. 点击“报告编辑”查看饮水保障一章。正文说明影响和责任；右侧“来源与计算”可以打开本段的关系、规则前提和真实原文。未确定的车辆数、到达时间不会由规则填补。
5. 回到输入确认，通过“修正”改变可用人数，先看影响预览，再应用。计算值更新，引用旧值的普通段落保留原样并提示核对；可以经助手修订或自己编辑保存，然后填写核对说明。不能直接手改可信测算块。
6. 在“审校发布”检查并导出 Word/PDF；同时下载“依据报告”，离线查看每个引用、规则结论及全部前提来源。正式稿不自动增加平台宣传话术或固定文种副标题。存在未核对段落时阻止正式导出；历史文稿不会因新计算被覆盖。

切换为“只检索原文”会清除该章原有关系和规则配置。重新准备后没有匹配依据，也可以确认本次空结果，将原有结论标为待更新；空结果不是“业务上没有风险”。

这里的本体不是写作文案模板：它约束“安置点、供水设施、责任单位”是什么对象以及哪些关系可用于本章。图谱检索把分散在不同材料里的关系连接起来；Semantica从前提推导影响；Agent负责将这些已有和推导依据写成自然正文。三者都不能证明缺失材料中不存在风险。

选中文字后右键可进行扩写、改写、缩写。纯文字修订会核对当前项目上下文，不会仅因原文出现“数量”就被要求执行数据库查询；“核验事实”“补充依据”仍走证据工具。建议必须通过检查，不能附带工具执行摘要、原文没有的引用或无变化结果，用户点击应用后才写入。

## 新增接口

`GET /api/v1/writing/knowledge-options`：当前用户可读的已发布语义模型与可用规则版本。

`GET /api/v1/writing/projects/{id}/chapter-evidence`：当前已应用依据及准备状态。

`POST /api/v1/writing/projects/{id}/chapter-evidence/preview`：固定知识范围内真实图关系检索和Semantica预演。

`POST /api/v1/writing/projects/{id}/chapter-evidence/{run_id}/apply`：校验并确认依据；不写正文、不发布组织图谱。

`GET /api/v1/writing/projects/{id}/chapter-evidence/source/{chunk_id}`：重新鉴权、校验快照后读取来源。

`GET /api/v1/writing/documents/{id}/paragraph-evidence`：按当前文稿段落返回引用、计算依赖与待更新状态。

`POST /api/v1/writing/documents/{id}/paragraphs/{block_id}/review`：用户核对已保存的普通段落，必须提交当前版本和原因；不能借此修改或认证测算/推演结果。
