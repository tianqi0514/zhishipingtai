# 妙笔按钮审计规则

每个按钮必须同时具备业务步骤、用户目的、实际接口或编辑器行为、成功反馈和失败处理。缺少任一项的按钮不进入普通界面。

## 保留的主操作

| 所属步骤 | 主操作 | 结果 |
|---|---|---|
| 明确任务 | 新建文章 | 创建文章级写作契约并进入 Plate |
| 准备资料 | 上传资料 / 从智库选择 | 形成固定版本的文章资料候选 |
| 信息确认 | 确认 / 修正 | 保存事实新版本和审计记录 |
| 起草 | 生成文章初稿 / 生成本章 | 创建可编辑正文和来源绑定 |
| 修改 | 接受 / 拒绝建议 | 形成明确正文变更 |
| 依据变化 | 查看影响 / 应用修改 | 重算并创建新文稿版本 |
| 检查导出 | 执行审校 / 导出 Word | 形成审校结果或真实文件 |

## 合并或弱化

- “分析计算、推演工具箱、方案比较”合并为按需的“分析与计算”，无需求时不显示。
- “插入测算块、插入方案块”改为“采用结果”，由系统维护正文绑定。
- 模板、规则、模型路由和技术参数移出普通作者主流程。
- 测试环境/生产环境发布、应用别名等不属于写作流程，不出现在妙笔。
- `/` 菜单、右键菜单和二级菜单承载低频格式与 AI 编辑能力，避免工具栏堆满按钮。
