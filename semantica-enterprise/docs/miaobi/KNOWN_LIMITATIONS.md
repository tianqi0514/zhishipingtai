# 妙笔写作工作台已知限制

- 完整 Plate 编辑器资源包较大，首次进入编辑器仍需进一步做插件级代码拆分。
- 项目内可绑定一个主要知识空间；多空间联合写作仍通过后台知识产品能力兼容，普通界面暂未开放复杂组合。
- 章节级生成可以跳过未就绪章节；对已有人工正文的自动章节合并仍需继续加强，建议通过右侧局部修订避免整篇覆盖。
- 来源文本变化可以可靠标记已登记 Chunk/事实/计算/推演绑定；无绑定的语义相似文字只能提示，不能保证全部联动。
- ContentElement 级治理变更当前采用文档版本范围的保守失效策略，精确到元素—Chunk 的映射仍可优化。
- DOCX/PDF 通用模板已经可用，客户正式版记、专用字体和签发流程需按交付规范配置。
- Semantica 只承担当前已验证的关系规则推演；数值比较先由确定性判据形成事实，不能把大模型或普通条件判断冒充正式推演。
- 自动审校不能替代客户业务批准和正式签发责任。
- 完整 Plate 生产包仍有大 Chunk 构建告警，当前不影响功能，但首次打开编辑器仍需要继续按插件域拆包和实测弱网性能。
- 没有显式 ChunkBinding 的相似叙述只能作为疑似影响提示，系统不会为了“全局更新”而执行字符串替换或整篇重写。
- 协同服务默认只绑定服务器回环地址；远程直连部署必须显式配置 `COLLABORATION_BIND_ADDRESS` 或通过同源反向代理暴露 WebSocket，不能仅凭本地缓存通道宣称协同正常。
- 测试文章达到业务讨论稿质量，但响应等级、行政职责、跨区域调度、正式版记和签发仍需要客户有权人员确认。
