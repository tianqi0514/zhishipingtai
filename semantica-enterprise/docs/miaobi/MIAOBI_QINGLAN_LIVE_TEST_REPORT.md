## 本轮发现及修复

1. **人工治理与语义模型候选脱节**：原候选接口统计自动抽取原字段，没有读取治理叠加后的有效类型、关系和证据。已修复，并保留人工审核决策与可恢复历史。代码 `249b666` 已推送并重建服务器。无网络、只读、SQLite 内存隔离测试：指定 7 项，加相邻治理共 23/23 通过。
2. **报告输出封装不兼容**：首轮真实 DSH 产生8个Step、11次工具调用，最终分章节JSON外有代码围栏并带工作前言，原解析器拒绝。第二轮工作前言包含合法引用标记，过严的数组检测也拒绝。两次失败run分别为 `880a95c4-72b2-484d-8961-b9c5c5526c33`、`7b81d081-ddb8-41bf-b648-d048b724b4ed`，均保留失败。现支持唯一完整JSON的封装规范化；多对象、数组包裹、不完整对象、尾随内容仍拒绝，工作前言不会进入正文。
3. **章节契约漏传引用约束**：第二轮原始JSON中的人员章节无引用。后端要求引用，生成提示却漏传citation_required、required_inputs、toolbox_outputs。现补齐实际章节契约，明确原始输入和计算结果的不同来源；没有修改或降低质量门。
4. **失败提示不明确**：422原来只显示“请求处理失败”，进度停留旧阶段。现读取安全业务错误、刷新本run真实终态，明确提示可重新生成。真实浏览器验证过失败提示及成功重试。
5. **人工审阅发现措辞归因不精确**：成功生成的第三章将清单500/320与计算180连写，容易误读为原清单已经列出缺口。已在Plate真实选择该短句并修改为“根据已确认输入，按需求减去可用人数测算，搜救人员缺口为180人”，保存新版本，未手改可信计算值。原AI稿与人工版均保留。自动质量门不代表逐句事实免审。
