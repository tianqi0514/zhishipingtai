# 妙笔写作工作台测试报告

## 本轮范围

本轮验证对象是“项目 → 多篇文章 → 资料准备 → 分章节起草 → Plate 编辑 → 依据与修改建议 → 检查导出”的写作闭环。测试不以页面数量或按钮数量作为完成依据。

## 自动化结果

- 写作域定向回归：136/136 通过。覆盖空白项目、后补知识空间、多文章业务范围、文章材料隔离、分章节可写性、人工正文防覆盖、来源版本、计算与推演绑定。
- 妙笔前端：35 项组件测试通过，TypeScript 检查通过，生产构建通过。
- Plate：真实 Plate 节点、斜杠命令、表格、评论、修订、引用与可信结果绑定均保留，不是 `textarea` 或静态 HTML 正文。
- Python 全量回归共收集 726 项。本机排除未安装可选 `docling` 的单项运行时能力检查后，708 项通过、17 项按环境条件跳过、1 项排除；Docker 生产镜像中的该 M4 能力实测 `ready_for_m4=True`，其中 Semantica、PDF、DOCX、PPTX、Excel、Docling、Pytesseract 和 Tesseract 均可用。

## 已修复问题

1. 空白项目被任意绑定到历史应急场景，普通用户看到疫情等无关技术输入。现改为后台通用写作契约。
2. 项目没有文章时仍初始化 Agent，并产生“未选择知识空间”错误。现只显示创建文章空状态。
3. 创建项目必须先理解知识产品 Release。现允许空白项目；知识空间是可选资料来源。
4. 生成前一个缺失输入封锁全文。现按章节判断，只生成具备依据和输入的章节。
5. 文章已有人工正文仍可能由整篇生成覆盖。现服务端拒绝覆盖，并引导使用章节或 Agent 修改建议。
6. 项目中的多篇文章共用材料选择。现文章分别固定采用的材料版本。

## 仍需关注

- 完整 Plate 功能带来较大的编辑器异步包，功能可用但仍需继续拆包和首开性能优化。
- 未建立依赖绑定的普通文字只能提示疑似影响，不能承诺自动联动。
- 自动审校不等于客户业务批准；定稿仍由业务责任人确认。
