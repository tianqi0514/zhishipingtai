# 妙笔三步写作主流程设计

## 1. 产品目标

妙笔的第一目标是稳定输出一篇结构正确、事实可信、可编辑、可导出的业务报告。用户只需要完成三件事：

1. 确认报告所需输入；
2. 查看系统完成的规则推演与确定性计算；
3. 在完整 Plate 编辑器中修改和发布报告。

“事实、规则、公式、算法、Agent、知识检索”继续由平台真实执行，但不再拆成普通用户必须理解的六个工作台。专业配置保留在配置中心。

## 2. 三步主流程

### 第一步：输入确认

系统从知识产品的已发布版本、上传材料、数据库查询与人工录入中形成报告输入清单。每一项展示名称、当前值、单位、来源、置信度、更新时间和确认状态。

用户可确认、修正或驳回。修正生成新事实版本，不覆盖历史值。报告生成前必须满足场景包的必填字段，存在缺失项、冲突项、低置信度关键项或待确认决策时阻止进入正式生成。

### 第二步：分析计算

“推演工具箱”由后端编排，对普通用户只展示业务结果：

- 确定性判据；
- Semantica 规则推演结论及证据链；
- 版本化公式计算结果；
- 结构化数据库实时查询结果；
- 路线或资源优化方案。

大模型只生成叙述性内容，不能生成权威数值或正式规则结论。工具箱输出保存运行标识、输入版本、规则/公式/算法版本、结果、证据和目标章节。

### 第三步：报告编辑

服务端按场景章节契约生成唯一的结构化章节输出。每章包含普通叙述内容与服务端注入的可信节点：

- `knowledge_citation`：知识来源；
- `computed_metric`：确定性计算；
- `inference_conclusion`：Semantica 推演；
- `alternative_plan`：算法方案；
- `manual_assumption`：明确的人工假设。

可信内容不以 HTML 标记展示。正文只显示轻量、可阅读的标记，完整依据位于右侧。完整 Plate 编辑能力继续保留，包括 `/` 指令、表格、图片、评论、修订、协同和版本。

## 3. 统一生成编排

新增 `WritingGenerationRun` 作为一次生成的权威业务记录：

1. 校验输入与确认闸门；
2. 执行/复用确定性计算；
3. 执行/复用 Semantica 推演；
4. 生成或选择方案；
5. 通过 DeepSeek Harness 按章生成叙述内容；
6. 后端解析严格章节结果；
7. 向章节插入可信业务节点；
8. 写入 Plate 原生节点与绑定；
9. 执行生产质量门；
10. 通过后形成不可变文稿版本。

任务阶段与百分比由实际步骤更新，不使用前端定时器伪造。失败时保存失败阶段与可操作错误，不留下半成品当前版本。

## 4. 章节契约

内部对象名称为 `ReportChunk`，用户界面统一称“章节内容”。每个章节至少包含：

- `section_key` 与稳定 `block_id`；
- 章节标题与写作目标；
- 允许使用的事实键；
- 目标计算、推演和方案结果；
- 引用要求；
- 结构化 Plate 节点；
- 质量检查结果。

Agent 不得输出整篇自由文本后直接拼接。每个章节只能生成一次；输出必须符合严格结构，出现自我对话、工具调用说明、内部实现或重复章节时自动重试一次，仍不合格则失败并阻止形成正式文稿。

## 5. 输入变化与应用更新

输入修正分为两个动作：

1. **预览影响**：在隔离快照中计算依赖链和新结果，不修改当前事实、正文或正式版本；
2. **应用更新**：用户确认后创建事实新版本、执行受影响计算/推演、更新关联可信节点并创建文稿新版本。

例如搜救人员可用量从 320 改为 400：预览必须显示搜救缺口从 180 变为 100，并列出受影响章节；床位和帐篷结果保持不变。取消预览不写入任何业务数据。

## 6. Agent 改稿

选中文本后右键提供扩写、改写、缩写、正式化、检查依据和转为待确认项。请求携带当前选区、所在章节、文稿版本、可访问知识版本和已有引用，由 DSH 生成修订建议。

建议先进入 Plate Suggestion，只有用户点击“应用修改”才进入正文；取消或拒绝不改变正文。右侧 Agent 支持整篇和指定章节的对话式修改，并展示真实工具事件和来源依据，不展示模型私有思维链。

## 7. 生产质量门

以下问题阻止正式 DOCX/PDF 导出和发布：

- 章节缺失、重复或顺序错误；
- 正文包含 Agent 自我对话、工具说明、内部标识或系统话术；
- 句子重复率高于 5%；
- 正文长度不在参考样稿的 75%—140% 范围（存在参考样稿时）；
- 关键数值与当前计算运行不一致；
- 推演结论没有有效 Semantica 运行与证据链；
- 正文存在失效、未确认或缺少绑定的可信节点；
- 引用不存在、越权或未指向锁定知识版本；
- 未完成必需人工确认节点。

审校返回问题、位置、原因和建议动作。不得再把结构不完整但“技术校验通过”的文稿标为可发布。

## 8. 导出契约

正式导出使用 A4，标题不带测试时间或内部版本后缀，正文显示可见引用编号。一次发布可以生成：

- 正式报告：面向业务阅读；
- 推演依据报告：事实、规则、公式、输入输出、证据链和版本清单。

两份文件分别保存校验值、文稿版本、知识产品版本和生成清单。正式文件不包含内部 UUID、Token、系统提示词或 Agent 工作过程。

## 9. 首轮验收重点

以客户原始样稿进行盲测，不把最终版 Word/PDF作为 Agent 生成来源，只用于质量比较。首轮必须修复此前 63/100 基线暴露的：章节 2—9 重复、正文工作话术、29.7% 重复句、Letter 页面、不可见引用、缺少计算/推演可信节点和虚假审校通过。

完成标准不是页面“看起来像应用”，而是上传客户材料后能够真实完成输入确认、工具箱运行、一键成稿、影响预览、局部更新、Agent 修订、质量审校和双文档导出。
