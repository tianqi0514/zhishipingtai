# 妙笔生产就绪度

## 当前结论

妙笔已从“展示很多模块的技术 Demo”收敛为以文章质量为中心的生产候选闭环：业务人员先确认报告输入，系统再执行确定性计算和 Semantica 规则推演，DeepSeek Harness 基于锁定的知识产品 Release 生成非推演章节，最终由完整 Plate 编辑器承载修改、引用核验和导出。

本轮客户样本盲测为 100/100，证明系统能够从上传材料产生结构完整、正文引用可核验、测算和推演可追溯的九章应急处置方案。该结论表示技术生产候选，不等同于客户对正式灾情、响应权限、公式参数和公文模板的业务签发。

## 已完成的产品收敛

- 主导航只保留“方案任务”和“报告编辑”。
- 方案任务严格采用“输入确认—分析计算—报告编辑”。
- 不再要求普通用户理解工具卡片、Chunk 模板或内部 ID。
- 计算结果自动匹配应出现的报告章节和可信块；用户只需预览并应用。
- 非推演内容由 Agent 撰写，进入正文前是建议，不静默覆盖人工内容。
- 正文保持普通文档阅读体验，详细来源、公式和证明链集中在右侧。
- 输入变化建立不可变新版本，相关指标、推演和正文绑定进入 stale/preview/apply 流程。
- Agent 写作 Session 与普通问答 Session 按 purpose 隔离，刷新和切换不会串流。

## 生产边界

- 正式业务发布前仍需客户确认灾情事实、响应权限、公式参数和签发流程。
- 路线方案当前使用受控算法及 fixture 数据；接入真实 GIS、交通、医院和资源系统后需重新验收。
- 协同当前采用单实例 Hocuspocus 持久化；水平扩容前需要共享协同存储。
- Reranker 未配置时继续明确降级到 RRF。
- 在线或内网大模型不可用时必须显示真实失败，不生成假文稿。
- 当前内网部署仍使用 HTTP 时只能作为受控测试环境；正式生产应启用 TLS。
- 浏览器测试工具本轮无法直接读取 Console 日志，只能确认页面无可见错误和服务日志无未处理异常。
