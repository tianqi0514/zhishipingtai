# 妙笔简化产品设计

## 产品目标

妙笔首先解决一个问题：普通业务人员如何基于已核验资料和确定性分析，快速得到一篇可继续编辑、可追溯、可更新的专业报告。

主流程固定为三段：

1. 输入确认：核对报告真正需要的数据及其来源。
2. 分析计算：系统一次执行公式计算、Semantica 规则推演、受控数据查询和方案算法。
3. 报告编辑：DeepSeek Harness 按章节组织非权威叙述，服务端插入可信数值、结论和引用，Plate 负责编辑。

数据变化不直接覆盖正文。系统先计算影响，用户点击“应用本次变化”后，才生成新的输入版本、计算运行和文稿版本。

## 面向用户的信息架构

妙笔只保留“写作任务”和“报告编辑”两个主入口。任务中仅有“输入确认—分析计算—报告编辑”三个阶段。公式、规则、章节映射和模型路由仍属于后台配置，不与普通写作流程争抢注意力。

正文以正常公文样式呈现。测算、推演和引用只显示轻量标记；点击标记后，依据在右侧展开。用户不需要理解 Plate、Datalog、Session Event、内部 ID 或工具参数。

## 能力边界

- Agent 负责目录、背景、衔接、扩写、改写、缩写和语气调整。
- 公式服务负责数值，Semantica 负责规则推演，结构化查询负责实时数据，算法服务负责路线和方案差异。
- Agent 可以描述权威结果，但不能修改结果。
- 报告生成只接受结构化章节产物；工作草稿、工具过程和模型私有思维链不得进入正文。
- 当前优先完成地震应急处置报告，不以换标题方式扩张其他灾种。

## 当前验收结论

客户材料盲测从旧版 63/100 提升到 100/100：九章唯一、重复长句为零、篇幅为客户样稿的 82.8%、正文无模型工作草稿，包含 4 个可信计算节点、1 个推演节点和 111 处可见引用。该结果代表技术和内容基线通过，不替代客户对正式口径和签发权限的业务确认。
