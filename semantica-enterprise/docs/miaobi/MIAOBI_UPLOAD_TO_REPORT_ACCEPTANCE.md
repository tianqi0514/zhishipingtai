# 妙笔：从材料上传到报告生成的完整验收脚本

## 验收目标

本脚本验证的不是编辑器控件本身，而是以下真实业务闭环：

材料上传 → 文档解析 → 知识加工 → 知识产品发布 → 妙笔任务锁定知识版本 → 事实核验 → 规则推演与确定性计算 → Agent 生成报告 → 正文引用绑定 → 审校与导出。

验收空间和材料均标记为演示数据，不代表实时灾情或正式指挥决定。测试不得修改其他知识空间。

## 演示前自动预检

在项目根目录执行：

```bash
export MIAOBI_DEMO_URL=http://127.0.0.1:8080
export MIAOBI_DEMO_USERNAME=admin
export MIAOBI_DEMO_PASSWORD='从安全环境变量读取'
python3 scripts/miaobi/acceptance_upload_to_report.py
```

脚本会幂等执行资料准备，并真实验证三份材料的解析、向量/图谱发布、知识版本锁定、三轮 DSH 写作对话、引用投影和报告质量。详细结果写入 `.demo-build/miaobi-upload-report-quality.json`。

## 浏览器验收步骤

### 1. 上传并形成知识供给

1. 登录传神智库，切换到“妙笔·地震应急知识空间”。
2. 进入“知识资产 → 文档”，上传：
   - `地震应急预案摘编（验收演示）.md`
   - `积石山县地震灾情与资源清单（验收演示）.yaml`
   - `地震应急方案章节与调度约束（验收演示）.json`
3. 加工方式选择“向量与图谱”。
4. 在任务中心确认每份材料依次完成解析、切片、语义抽取、向量索引和图谱发布；失败状态不能以“详情已完成”代替。
5. 打开文档详情，核对原文预览、解析结果、治理画像和来源位置。
6. 在知识产品中发布新 Release，记录版本号。

预期：三份材料均为当前有效版本；全文、向量和图谱均可用；Markdown 不调用 OCR。

### 2. 确认妙笔与智库的连接

1. 从应用中心打开“妙笔·应急方案生成”。
2. 选择“积石山县6.2级地震应急处置方案（验收演示）”。
3. 在任务概览检查“来自传神智库”区域。
4. 核对知识产品名称、Release 版本、来源文档数、知识片段数、图谱对象和知识关系数。
5. 点击“查看材料”和“查看图谱”，确认跳转后仍选中同一知识空间。
6. 如果出现“有新版本”，点击“采用最新知识”，确认已有正文依据被标记为需要核验，而不是静默替换。

预期：用户能直接看出妙笔使用哪一版智库知识，以及新知识如何进入方案任务。

### 3. 核验事实、推演和计算

1. 进入“数据与事实”，核对震级、人口密度、搜救人员、床位和帐篷数据。
2. 对待确认事实打开原始来源后再确认；修正值必须填写理由。
3. 进入“推演工作台”，运行灾害等级判据和 Semantica 规则推演。
4. 查看灾害等级结论的规则、前提和来源。
5. 运行资源缺口计算，核对：搜救人员缺口 180 人、县域床位缺口 220 张、全域床位缺口 80 张、帐篷缺口 1800 顶。
6. 进入“方案比较”，确认速度优先、安全优先和综合平衡三套方案的路线与权重确实不同。

预期：数值来自确定性计算，灾害等级来自规则推演，模型不能替代两者。

### 4. 使用完整 Plate 编辑器

1. 进入“妙笔文稿”，点击正文任意空段落。
2. 输入 `/`，确认弹出“妙笔与知识、基础内容、结构与专业内容”三组指令。
3. 分别插入标题、列表、待办、提示块、3×3 表格、三栏、日期、公式、脚注和图片。
4. 使用工具栏验证字体、字号、颜色、行距、对齐、缩进、链接、表格行列、撤销和重做。
5. 导入一份 DOCX，再分别执行 Markdown/HTML 导入和 Markdown 导出。
6. 选中文字添加评论；开启修订，输入文字后分别验证接受和拒绝。
7. 刷新页面，确认自动保存内容和评论仍存在。

预期：编辑器使用锁定版 Plate 插件体系，不是 textarea、contenteditable 壳或静态 HTML Demo。

### 5. 生成报告并绑定依据

在右侧“妙笔助手”依次发送：

1. `请严格使用已激活场景包生成方案目录草稿，保持总则、灾情研判、组织体系、应急保障、附则的顺序。`
2. `请检索当前锁定知识版本，核对灾害等级判据和应急处置依据；所有文档事实必须带真实引用。`
3. `请基于前两轮结果生成一份 800—1600 字的完整应急处置方案修订建议，覆盖灾情研判、组织体系、应急保障和附则，并使用已核验事实、确定性测算、规则推演和已选方案。`

检查：

- 执行过程出现真实项目上下文读取、知识检索和写作工具事件。
- 回答中的引用编号在服务端引用投影中存在。
- 点击“插入为修订建议”后，正文采用普通排版；依据只显示轻量 `[n]` 标记。
- 点击 `[n]` 后，右侧“引用依据”展示文档、页码/结构位置和完整片段。
- 测算和推演只显示轻量“测算/推演”标记，公式、输入、规则和前提在右侧查看。
- 接受修订前内容仍是建议状态。

### 6. 报告质量验收

报告满分 100，85 分为通过，70—84 分为有条件通过：

| 维度 | 分值 | 验收标准 |
|---|---:|---|
| 材料加工 | 20 | 三份材料真实解析，向量和图谱均发布 |
| 事实正确 | 30 | 7 个关键判据和缺口值与 Ground Truth 一致 |
| 章节结构 | 15 | 覆盖场景包要求且正文 600—3500 字符 |
| 证据绑定 | 15 | 正文引用均能关联服务端 Citation、QueryRun 和 Chunk |
| Agent 编排 | 10 | 真实调用项目上下文与知识检索工具 |
| 版本一致 | 5 | 方案任务锁定知识产品 Release，图谱/向量状态真实 |
| 输出安全 | 5 | 不出现工具名、UUID、凭据、系统提示词和内部实现字段 |

任何权威数值错误、引用不存在、使用旧知识版本或模型编造规则结论，均视为阻塞问题，即使总分超过 85 也不能发布。

## 用验收结果倒推平台优化

- 上传或解析失败：修复知识接入、模型路由或任务状态一致性，不在妙笔中绕过。
- 文档可搜但妙笔不可用：检查知识产品 Release 和应用授权。
- 事实缺失：将缺失项转为显式确认闸门；不要让模型补齐。
- 数值错误：修复公式输入绑定或结构化查询，不通过提示词“纠正”。
- 推演错误：修复事实、本体映射或 Semantica 规则及证据链。
- 引用错误：修复 QueryRun/Chunk/正文标记的服务端绑定，禁止只显示文本编号。
- 报告结构漂移：收紧场景包章节契约和写作工具 Schema。
- 正文出现内部技术词：在 Agent 输出投影和导出前做安全审校。
- 新知识静默覆盖正文：修复 stale 影响传播，要求用户确认后生成新版本。

只有在上述问题被修复并重新从上传步骤通过后，才能认定妙笔具备可演示的端到端能力。
