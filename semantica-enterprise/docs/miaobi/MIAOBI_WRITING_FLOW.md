# 妙笔写作主流程

## 1. 创建写作任务

用户选择场景和不可变知识产品 Release。Release 决定本次写作可以使用的文档版本、知识片段和图谱，不随知识空间后续变化而静默漂移。

## 2. 确认输入

输入表只显示业务名称、当前值、单位、来源、版本和状态。必需输入缺失、待确认或冲突时，服务端拒绝一键生成。

用户可以查看原始文档、工作表或数据查询来源；修正值必须填写理由。计算结果和推演结论不在输入区直接编辑。

## 3. 一键分析和生成

`POST /api/v1/writing/projects/{id}/generate-report` 创建不可变生成运行，依次完成：

1. 锁定 Release、场景和输入版本。
2. 校验全部必需输入。
3. 执行确定性计算、Semantica 推演和方案算法。
4. 按报告模板建立九章内容计划。
5. 通过 DeepSeek Harness 为每章执行真实 Agent Turn。
6. 严格解析结构化章节结果，过滤工作草稿和内部说明。
7. 服务端插入可信数值、推演结论和有效引用。
8. 运行篇幅、章节唯一、重复率、引用和可信块质量门禁。
9. 只有通过门禁才写入新的草稿版本。

## 4. Plate 编辑

编辑器保留完整 Plate 能力，包括 `/` 指令、标题、列表、表格、图片、引用、评论、修订、协同、自动保存和版本。可信节点在正文中只显示轻量标记，完整依据统一在右侧展示。

选中文字后可执行扩写、改写和缩写。Agent 先生成建议，用户接受后才写入新版本；受保护数值、推演结论和引用不能被 Agent 篡改。

## 5. 数据变化

输入修正先调用预览接口，返回旧值、新值、受影响计算和正文内容。用户取消时不改变正式数据；用户应用后才局部重算并生成新文稿版本。历史版本保持不可变。

已验证用例：可用搜救人员由 320 人改为 400 人，搜救人员缺口由 180 人变为 100 人，只影响 1 个关联正文内容；恢复为 320 人后重新得到 180 人。
