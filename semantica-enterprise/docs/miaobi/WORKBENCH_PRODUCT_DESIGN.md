# 妙笔写作工作台产品设计

## 产品边界

妙笔是独立写作产品。用户围绕“项目—文章”工作：一个项目管理团队、资料池和共享事实，一篇文章独立管理目的、读者、适用范围、采用材料、目录、正文、引用和版本。知识底座继续负责解析、切片、检索、图谱、来源版本和权限；妙笔不复制这些能力，也不要求作者理解知识产品 Release、Datalog 或 Query IR。

## 三个界面阶段与七步业务

界面只保留“准备资料—起草编辑—检查导出”。内部七步为明确任务、准备资料、确认信息与目录、按需分析、生成初稿、修改审校、定稿导出。步骤不是强制关卡：空白文章可以直接编辑，缺少事实只阻塞依赖它的章节。

## 页面

1. 项目列表：创建、选择和归档项目。
2. 项目详情：文章列表、项目资料池以及关键信息。
3. 写作工作区：左侧目录，中间完整 Plate，右侧助手、依据和审校。

项目创建只需要名称和可选事项说明、知识空间。编码和不可变知识版本由后台管理。文章创建需要名称、类型，可选填写读者、用途、适用范围与要求，完成后直接进入编辑器。

## 可信写作规则

- 样稿只影响结构、表达和排版，不成为业务事实。
- 文章只检索“用于本文”的固定材料版本。
- 模型文字作为草稿或修订建议，不静默覆盖人工正文。
- 权威数值来自公式或受控数据库查询。
- 正式关系结论来自 Semantica，并保留前提和证明。
- 来源变化先形成影响预览，应用后才生成新版本。
- 无绑定的相似文字只提示疑似影响，不承诺自动联动。

## 业务状态

章节状态为“可起草、需补充、需确认、需计算”。文稿状态为草稿、审校中、已定稿、已归档。来源状态为当前有效、历史版本、待核验、已失效。它们彼此独立，避免一个缺项锁死整篇文章。

## 删除的复杂度

普通写作页面不再出现应用发布环境、生产别名、Agent Profile、规则变量、Query IR、场景包版本和内部 UUID。管理员配置不放在写作顶栏；只有会实际改变目录、必填信息、工具、文风、导出或审校结果的配置才保留在后台。
