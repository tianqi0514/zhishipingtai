# 前端缓存与请求生命周期

## 缓存策略

前端只缓存低风险、短期可复用的查询结果，例如知识空间、字典项和页面概览。缓存键包含接口和参数，空间级数据必须包含 `space_id`。

`cachedApi` 提供：

- TTL 内直接复用；
- stale-while-revalidate，在允许范围内先展示旧值再后台更新；
- 相同键的并发请求合并；
- 写操作后的精确失效；
- 空间切换时清理旧空间键。

鉴权、写操作、任务状态轮询、SSE 和必须强一致的详情不使用陈旧缓存。

## 请求取消与竞态处理

每次页面导航创建新的 `AbortController` 和单调递增请求序号。视图切换时取消旧请求；返回结果时再次比较序号。两层保护用于处理不支持取消的边界服务和浏览器缓存命中后的微任务竞态。

独立长连接同样有清理责任：

- 对话页面离开时关闭旧 SSE；
- 检索请求离开时取消；
- 图谱页面离开时销毁 3D 实例；
- 轮询和计时器集中登记并清理。

## 写后失效

| 写操作 | 失效范围 |
| --- | --- |
| 新建/编辑/删除空间 | 空间列表、工作台；删除时清除该空间全部缓存 |
| 上传/重新加工文档 | 文档列表、治理概览、任务、发布记录 |
| 新建/同步数据源 | 数据源、文档、任务、治理概览 |
| 内容或图谱治理 | 治理概览、图谱、发布记录、检索相关摘要 |
| 发布/撤回规则推演 | 规则推演、图谱、发布记录、治理概览 |

## 失败行为

- 被取消请求不显示错误提示。
- 当前页面真实失败时保留框架并显示可重试状态。
- 一个检索通道失败不清空其他通道已有结果。
- 写请求没有自动重试，防止重复创建；按钮在提交期间禁用。
