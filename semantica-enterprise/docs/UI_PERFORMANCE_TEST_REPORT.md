# UI 性能测试报告

测试日期：2026-09-04

分支：`codex/business-journey-ui-ux`

环境：Docker Desktop，本地 `http://localhost:8080/`，已有数据 Volume 保留

## 基线与结果

改造前实测一次“文档 → 空间”切换约 3068 ms，并发生 6 次公共查询。根因是每个页面串行刷新相同 lookup、旧请求无法取消、页面无缓存且视图切换后仍继续写入。

改造后在同一浏览器连续点击 20 个一级/二级入口：

| 页面 | 应用内部完成时间 | 单次导航重复请求 |
| --- | ---: | ---: |
| 治理概览（缓存） | 3–4 ms | 0 |
| 数据接入 | 4–29 ms | 0 |
| 知识资产 | 4–5 ms | 0 |
| 工作台 | 5–6 ms | 0 |
| 配置中心 | 117–140 ms | 0 |
| 系统管理 | 134–157 ms | 0 |
| 知识检索 | 89–167 ms | 0 |
| 运营中心 | 850–1070 ms | 0 |

浏览器自动化框架一次 Locator 点击本身约有 3.1 秒外部动作等待，因此报告采用页面内真实导航诊断时间，不把自动化框架等待误算为应用渲染耗时。

## 稳定性

- 连续切换 20 次，没有旧页面内容覆盖新页面。
- 连续切换治理子页 5 次后，活跃图谱实例为 0、计时器为 0、请求为 0。
- 注入 `window.error` 和 `unhandledrejection` 监听后记录为 0。
- 1280×720 和 1440×900 的页面主体无非预期横向溢出。
- 浏览器后退、前进和强制刷新均恢复页面和当前知识空间。

## 说明

本轮没有虚构大规模压测结论。数值来自真实浏览器导航；后台模型、媒体和语义抽取耗时属于长任务，不以 UI 缓存掩盖，页面仍展示真实状态和百分比。
