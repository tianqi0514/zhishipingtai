# 产品缺口登记簿

## 初始审计（开发前）

| 编号 | 级别 | 缺口 | 业务影响 | 处置状态 |
|---|---|---|---|---|
| PG-001 | P1 | 现有数据是技术验收集，组织仅 2 个、用户仅 1 个 | 无法证明集团层级、角色和空间隔离可交付 | 待建立集团合成数据 |
| PG-002 | P1 | 现有产品文档没有机器可验证的集团业务标准答案 | 测试只能判断接口成功，无法证明回答正确 | 待建立答案清单和断言脚本 |
| PG-003 | P1 | 应用反馈转治理已实现，但治理发布后重新评测的业务状态与入口尚未证明 | 应用质量闭环可能停在“已转治理” | 待真实闭环测试并修复 |
| PG-004 | P2 | 工作台显示指标和快捷操作，但没有按系统真实状态给首次管理员唯一下一步 | 新管理员可能不知道先建组织、空间还是模型 | 待业务走查后优化 |
| PG-005 | P2 | 数据源同步任务、文档版本和加工任务之间的页面跳转需逐项验证 | 用户难以判断“同步成功”和“可检索” | 待浏览器验证 |
| PG-006 | P2 | `process_knowledge` 等任务类型仍在工作台直接显示英文内部名 | 普通用户不易理解 | 待统一业务标签 |
| PG-007 | P2 | 历史失败任务保留在工作台但缺少聚合原因/下一步判断 | 管理员无法快速判断是否需处理 | 待运营页面验证 |
| PG-008 | P2 | 应用正式运行 API 当前以场景检索为主，场景化 Agent 问答能力需确认产品定位 | 应用构建可能只覆盖检索型应用 | 待架构与业务验收 |
| PG-009 | P3 | DSH 合约测试正确命令依赖 Agent Runtime/tsx 环境，README 容易被误用 | 交付人员会得到假失败 | 待更新测试入口 |

本表在每轮回归后更新“根因、修复提交、验证证据和遗留风险”。P0/P1 未关闭前不得宣布完成。
