# 应用构建工作台业务化改造说明

## 改造原因

原“应用支撑”直接向用户展示应用凭据、Knowledge Product、Scenario Version、Grant 和 Evaluation Run。底层模型正确，但普通用户无法判断应该先做什么，也无法知道应用是否已经具备上线条件。

本轮只重构业务入口和操作路径，不改变 A0 数据模型、鉴权、不可变版本或 Semantica/DeepSeek Harness 边界。

## 新的业务流程

```text
应用工作台
→ 知识供给
→ 能力场景
→ 上线测试
→ 接入发布
→ 运行反馈
```

| 页面业务名称 | 对用户的含义 | 继续复用的后台对象 |
|---|---|---|
| 应用工作台 | 创建应用并查看完整上线进度 | `Application`、授权、凭据、评测运行和反馈聚合 |
| 知识供给 | 选择应用可以使用的知识并固定正式版本 | `KnowledgeProduct`、`KnowledgeProductRelease`、Alias |
| 能力场景 | 定义检索、问答、分析或结构化输出能力 | `ApplicationScenario`、不可变 Scenario Version |
| 上线测试 | 用真实业务问题判断能力能否上线 | Evaluation Dataset、Case、Run、Recall/MRR/NDCG |
| 接入发布 | 开放知识与场景权限，生成接入凭据 | Grant、Scrypt Secret、短期应用 JWT |
| 运行反馈 | 把线上问题转回知识治理 | `ApplicationFeedback`、现有 `CurationCase` |

## 应用工作台

工作台以“一个业务应用”为中心，展示：

- 应用用途、状态和运行环境。
- 已关联的知识供给。
- 已关联的能力场景。
- 已通过的真实上线测试。
- 当前有效接入凭据。
- 运行反馈数量。
- 当前缺失环节和唯一的“继续配置”动作。

上线准备度由四个可核验条件组成，每项 25%：

1. 应用具有知识产品 `read` 授权，且该知识供给配置了 production 版本。
2. 应用具有场景 `invoke` 授权，且该场景已发布当前版本。
3. 当前场景版本至少存在一次通过质量门禁的真实 Evaluation Run。
4. 应用同时具有知识、场景授权和至少一个未撤销、未过期的凭据。

四项全部满足，且应用为 active/enabled 时，页面才显示“可以接入”。进度不使用定时器或静态假数据。

## 引导式关联

新建应用不要求用户先理解 Grant：

- “选择知识供给”会调用真实 `/applications/{id}/grants` 创建 `knowledge_product/read/allow` 授权。
- “选择能力场景”会调用同一接口创建 `scenario/invoke/allow` 授权。
- 底层仍保留 deny 优先和最小权限校验。
- 高级授权、凭据轮换和撤销集中在“接入发布”。

## 业务语言与技术信息

- Knowledge Product 在页面显示为“知识供给”。
- Scenario 显示为“能力场景”。
- Evaluation 显示为“上线测试”。
- Credential/Grant 集中显示为“接入凭据”和“开放范围”。
- Checksum、内部编码、JSON Schema 等信息移入“技术信息”或“技术选项”。
- 每个页面提供按需打开的“功能说明”，不在主页面长期堆叠解释文字。

## 与 Semantica 的关系

- 知识供给仍引用现有 `KnowledgeRelease`，不复制 Semantica 解析、切片、抽取、图谱或向量结果。
- 能力场景仍调用现有混合检索、Semantica SearchRanker 和 Provenance。
- 上线测试仍发起真实检索并计算确定性指标，不使用静态结果伪造通过。
- 运行反馈仍转换为现有人工治理 Case，不覆盖 Semantica 自动结果。
- DeepSeek Harness 的对话场景仍按既定低耦合边界接入；本轮没有修改 Agent Loop。

## 验收结果

| 项目 | 结果 |
|---|---|
| 自动化测试 | 132/132 单元/API 测试通过；19/19 Semantica/平台合约测试通过 |
| 六步导航 | 应用工作台、知识供给、能力场景、上线测试、接入发布、运行反馈全部真实点击通过 |
| 功能说明 | 六个页面显示各自不同的业务说明 |
| 引导式创建 | 临时应用从 0% 开始；关联正式知识后为 25%；关联已有场景后识别真实测试结果并达到 75% |
| 临时数据 | 引导测试应用通过正式 API 清理，未遗留有效测试应用 |
| 取消操作 | 创建应用弹窗点击取消不提交、不提示校验错误，应用数量不变 |
| 响应式 | 1280×720、1440×900 六个页面无整体或内容区横向溢出，内容区可独立纵向滚动 |
| 浏览器控制台 | 0 错误、0 警告 |

保留的 `foundation_acceptance` 应用目前显示 75%，原因是验收结束后主动撤销了全部测试凭据；知识供给、能力场景和上线测试均已完成。这是平台真实安全状态，不是缺失数据。
