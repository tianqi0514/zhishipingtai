# 业务旅程 UI/UX 设计与实现

## 目标

本轮不改变 FastAPI、Worker、Semantica 适配器、DeepSeek Harness 和各存储组件的技术边界，而是把页面从“系统对象清单”重组为业务人员能够连续完成的知识旅程：

> 选择知识空间 → 接入或上传 → 自动加工 → 人工治理 → 发布知识 → 检索/问答 → 构建应用 → 运营改进

左侧只保留九个一级业务域：工作台、知识资产、数据接入、知识治理、知识服务、应用构建、运营中心、配置中心、系统管理。知识空间是业务上下文，不是普通筛选条件；空间切换后，所有空间级页面共同联动。

## 关键闭环

| 用户动作 | 完成后的去向 | 系统给出的真实下一步 |
| --- | --- | --- |
| 新建知识空间 | 自动设为当前空间并进入文档列表 | 上传文档、选择数据源 |
| 上传文档 | 留在文档列表并显示加工状态 | 查看任务、打开文档详情 |
| 新建数据源 | 进入该数据源详情 | 测试连接、同步数据 |
| 文档仅检索加工 | 文档详情 | 验证知识检索、查看加工任务 |
| 文档仅图谱加工 | 文档详情 | 查看知识图谱、查看发布记录 |
| 文档同时加工 | 文档详情 | 查看知识图谱、验证知识检索 |
| 自动加工完成 | 知识治理概览 | 内容治理、图谱核验、规则推演、发布记录 |
| 知识发布完成 | 知识服务 | 检索、智能问答、服务开放 |
| 知识服务验证完成 | 应用构建 | 配置知识供给、能力场景、上线测试与发布 |

页面中的“下一步”均为真实路由和真实后台能力，不使用装饰性按钮。

## 知识治理整合

知识图谱和规则推演都移动到“知识治理”，原因不是改变其底层实现，而是二者都在决定“哪些知识进入正式供给”：

- 内容治理处理文档、Chunk、实体和事实的人工校正。
- 知识图谱负责核验、编辑和发布实体关系。
- 规则推演用已发布事实发现可证明的新结论。
- 发布记录展示图谱、索引和知识发布的版本边界。

原有 Hash 路由 `#knowledge`、`#analysis`、`#releases` 保持兼容，REST、MCP、CLI 和 DeepSeek Harness 协议没有因导航调整而改变。

## 交互原则

1. 用户完成动作后，页面必须进入可继续工作的状态，而不是停留在失去上下文的列表。
2. 页面先显示当前空间、真实状态和主操作，再显示技术细节。
3. 空状态说明“为什么为空”，并给出可执行下一步。
4. 成功提示只显示一次，刷新和后退不会重复弹出。
5. 加载使用结构骨架，旧页面请求在切换时取消，避免内容串页。
6. 失败必须保留原状态并给出重试入口；不能用绿色完成状态隐藏部分失败。

## 技术边界

- Semantica 继续承担解析、切片、语义抽取、归一化、推理、溯源和排名等能力。
- FastAPI 继续承担身份、权限、知识空间、版本、发布和稳定业务 API。
- Worker 继续承担长任务；本轮只修正部分抽取失败的状态表达和后续调度边界。
- DeepSeek Harness 继续承担 Agent Loop 与 Session Event，前端不伪造执行过程。
- OpenSearch、Qdrant、FalkorDB 的发布与查询职责未改变。

## 兼容性

- 旧书签和浏览器前进/后退可继续使用。
- 刷新后恢复当前知识空间和合法页面。
- 平台级页面不会被错误套用空间过滤。
- 原有数据、文档版本、索引、图谱和 Docker Volume 未被删除。
