# 知识应用开发者指南

## 五步上线

### 1. 准备知识供给

选择一个或多个已有权限的知识空间，创建不可变知识版本。`development`、`testing`、`production` 别名用于控制各环境实际使用的版本。

上游空间更新后页面会提示差异。创建新知识版本不会自动改变生产应用；应先测试再切换 `production`。

### 2. 发布能力场景

场景定义应用的业务能力、知识供给、检索通道、模型和引用策略。每次修改生成新版本，不覆盖历史。

当前应用 Runtime 的稳定对外能力是权限受控的场景检索；平台内智能问答由 DeepSeek Harness Agent 驱动。需要向第三方应用开放完整 Agent 对话时，应使用平台会话 API，而不是把一次检索调用描述为完整 Agent。

### 3. 运行上线测试

测试集中的每个问题至少配置一个可核验标准片段。运行会调用真实检索链路，并计算 Recall@K、MRR、NDCG 等确定性指标。

门禁未通过时不要生成生产接入凭据。先检查知识范围、解析结果、检索通道和标准依据是否正确。

### 4. 接入发布

应用必须同时获得知识供给读取权限和场景调用权限。凭据使用最小 Scope，Secret 仅显示一次；轮换或撤销后旧令牌立即失效。

调用顺序：

1. 使用 Client ID/Secret 换取短期 Token；
2. 调用场景 Runtime；
3. 保存响应中的请求、查询、知识版本和引用标识；
4. 通过反馈接口提交业务问题。

### 5. 运行反馈闭环

错误、不完整、过期、引用错误等反馈可以转为治理任务。治理人员修正并发布后，反馈进入“待验证”；应用开发者重新运行上线测试，选择通过门禁且场景一致的测试结果确认修复，系统才将反馈标记为“已解决”。

该过程会保存反馈、治理任务、人工决定、发布任务和 Evaluation Run 的关联证据。

## 禁止事项

- 不把数据库密码、模型 Key 或平台服务 Token放在应用配置中。
- 不让应用直接访问 PostgreSQL、OpenSearch、Qdrant、FalkorDB 或数据源数据库。
- 不绕过知识供给版本直接指定空间内部投影。
- 不以静态接口 200 代替业务答案和引用验收。
- 不把未通过上线门禁的版本切换到生产别名。
