# 智慧流程中枢客户演示库验证记录

## 验证范围

本记录覆盖独立知识空间、客户原始材料、补充业务 fixture、多数据源同步、多格式解析、自动治理、知识图谱、全文/向量/图谱三路检索、DeepSeek Harness 多轮问答和浏览器关键流程。

## 数据边界

- 客户原始材料：采购制度、“三重一大”制度、采购控制表、项目报告和招标公示。
- 演示补充数据：流程台账、风险事件、接口目录、督办邮件、Web/REST/RSS/Sitemap 服务、本地目录和 MinIO 对象。
- 补充数据均为不含敏感信息的确定性演示 fixture，不作为客户真实生产事实。

## 自动化准备方式

- `tests/e2e/seed_smart_process_demo.py`：幂等创建/复用演示空间、上传材料、创建数据源、执行同步、等待加工、补充带证据图谱事实、执行三路检索和三轮问答验收。
- `tests/fixtures/smart_process_source_server.py`：提供可重复的 Web、REST、RSS、Sitemap 真实协议响应。
- `tests/fixtures/smart-process-demo/`：提供 CSV、JSONL、EML、JSON 和 Markdown 业务 fixture。

## 已发现并修复的问题

| 问题 | 根因 | 修复 |
|---|---|---|
| 本地挂载目录首次同步无法写入 | 历史测试创建的来源目录归属为 root | 修正运行目录权限，演示目录由应用用户持有 |
| 长文档语义建模在 60 秒后部分失败 | 默认云模型超时不足以覆盖长制度文档 | 将当前平台 Kimi 配置调整为 180 秒；保留部分失败降级，不让已解析内容丢失 |
| 混合格式发布时 OpenSearch 批量写入失败 | 不同解析器的 `source_span` 嵌套结构不同，动态映射发生文本/对象冲突 | `source_span` 完整保留在 `_source` 中但不对嵌套字段建索引；批量异常返回具体失败项 |
| 同一 DOCX 表格片段在召回中重复出现 | 解析器可生成内容相同但 Chunk ID 不同的片段 | 在 RRF 前按文档版本与规范化内容去重，保留跨文档佐证 |
| 人工创建图谱关系不能进入图谱检索证据 | 创建接口没有接收来源 Chunk | 增加同租户、同空间、当前发布版本的 `source_chunk_id` 校验与持久化 |
| 多个加工任务同时发布时偶发索引或图谱版本竞争 | 发布序号和同空间当前版本切换缺少跨进程互斥 | PostgreSQL 事务级 advisory lock 串行化同租户、同空间发布，保持旧版本可用 |
