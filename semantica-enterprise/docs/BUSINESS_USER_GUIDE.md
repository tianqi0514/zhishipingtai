# 传神智库业务使用手册

本文按国联集团真实建设顺序说明各角色如何使用系统。平台不是“上传后就结束”的文档仓库；完整业务链是：

> 组织与权限 → 平台能力配置 → 知识接入 → 自动加工与治理 → 人工修正 → 检索/分析验证 → 知识供给发布 → 应用上线测试 → 运行反馈闭环

## 1. 角色分工

| 角色 | 主要工作 | 不应获得的权限 |
|---|---|---|
| 集团知识管理员 | 建组织、角色、空间，配置模型和策略，处理跨部门治理问题 | 无限制业务数据库写权限 |
| 子企业知识管理员 | 管理本单位空间、文档、数据源和治理结果 | 其他单位私有空间 |
| 部门知识维护员 | 上传和更新本部门材料，查看加工结果，处理本部门治理事项 | 平台模型、系统用户等全局配置 |
| 普通员工 | 在授权空间检索、问答、查看引用 | 文档修改、配置和越权片段 |
| 知识应用开发者 | 组合知识供给、能力场景、上线测试和接入凭据 | 数据库 Secret、其他开发者应用 |
| 只读审计员 | 查看审计记录和交付证据 | 知识与应用修改能力 |

## 2. 首次建设

### 2.1 建立组织与人员

1. 进入“系统管理 → 组织机构”，按集团、子企业、部门建立层级。
2. 在“角色权限”创建职责角色；平台权限控制模块能力，知识空间授权控制内容范围。
3. 在“用户管理”创建用户，绑定组织和角色。
4. 用非管理员账号重新登录，确认左侧模块和数据范围符合职责。

输出：可审计的组织、用户、角色和平台权限。验收时必须验证不同单位之间的显式拒绝和默认拒绝。

### 2.2 配置模型和加工策略

1. 在“配置中心 → 模型服务”配置 LLM、Embedding；Reranker、Vision、ASR 按实际采购情况配置。
2. 使用“测试”发起真实最小请求。成功只代表当前配置实际可调用，不代表静态表单校验通过。
3. 在解析、切片、抽取和治理策略中设置默认项。
4. 未配置 Vision/ASR 时，图片和音视频只使用 OCR/媒体元数据等真实可用能力，页面会显示降级状态。

输出：可版本化、可测试、密钥不回显的模型和处理策略。

### 2.3 建立知识空间和授权

1. 按业务边界建空间，例如“集团制度知识库”“产品知识库”“供应商与采购知识库”。
2. 指定负责人。
3. 给组织、角色或用户授予读取、编辑或管理权限。
4. 用测试账号验证：能看到授权空间，不能检索或打开未授权空间的片段。

空间是文档、图谱、检索、应用知识供给和权限隔离的共同边界，不建议按文件格式建立空间。

## 3. 接入和加工知识

### 3.1 文件上传

1. 进入“知识资产 → 文档资产”，选择知识空间并上传文件。
2. 页面显示当前支持格式；PDF、Office、扫描件、图片、邮件、音视频和安全 ZIP 会进入相应解析链。
3. 在文档详情或任务中心观察真实百分比和步骤。
4. 解析成功后检查元素、Chunk、治理画像、实体、事实、图谱版本和索引版本。

上传新版本时会保留旧版本。文件选择弹窗取消不会触发表单校验。正在解析或加工的文档禁止删除，以避免孤儿任务和投影污染。

### 3.2 数据源接入

1. 进入“数据接入”，先从类型卡片选择 Web、REST、数据库、邮件、对象存储等来源。
2. 填写连接配置并执行真实连接测试。
3. 配置同步范围、增量游标、定时计划和知识索引开关。
4. 手工同步一次，查看同步结果、文档版本和后续加工任务。
5. 内容未变化时再次同步应返回 `unchanged`；发生变化时只创建新版本并加工变化内容。

数据库来源还应按“结构发现 → 数据预览 → 语义映射 → 查询测试”使用。关闭“知识索引”时只做实时预览/语义查询，不应自动启动文档知识加工。

### 3.3 自动治理和人工治理

Semantica 自动生成解析元素、摘要、分类、质量指标、实体、关系和来源证据。人工治理不覆盖原始自动结果，而是增加可回滚的覆盖层。

1. 在文档详情先检查自动治理画像和问题。
2. 在“治理工作台”选择待办或主动查找目标。
3. 对画像、原文元素、Chunk、实体或事实执行接受、修正、屏蔽、合并等操作。
4. 查看影响预览后发布；发布会更新当前知识版本及搜索/图谱投影。
5. 如结果不符合预期，从发布记录回滚。

输出：保留原始值、人工原因、操作者、批次、发布任务和回滚记录的可追溯知识版本。

## 4. 验证知识是否真的可用

### 4.1 智能问答

1. 进入“知识服务 → 智能问答”，选择一个或多个知识空间。
2. 保持全文、向量、图谱至少一个通道启用；未配置模型的通道会真实降级。
3. 连续提出事实问题、指代追问、比较问题和页码依据问题。
4. 中栏查看流式回答，右栏检查 Agent 执行过程、检索轨迹和最终排序依据。
5. 点击引用打开真实文档片段，核对文档、页码/时间区间和结构位置。

“执行过程”来自 DeepSeek Harness Session Event，不展示或伪造模型私有思维链。证据不足时系统应明确说明，而不是编造集团事实。

### 4.2 图谱和知识分析

- 知识图谱用于查看和维护实体关系；节点和边的修改会形成真实版本并发布。
- 规则中心把专家经验转为 Datalog 规则。
- 场景分析组合规则、知识范围和运行参数。
- 推理结果展示结论、前提、来源证据、发布和回滚。
- 高级查询使用 SPARQL 精确检查图谱和推理事实。

建议先完成检索和引用验证，再开展规则推理，避免在低质量原始知识上放大错误。

### 4.3 结构化经营数据

1. 在数据库数据源详情执行 Schema 发现并查看漂移。
2. 在数据预览中验证实时数据库与同步快照；敏感字段由服务端隐藏或脱敏。
3. 将表、字段、主外键映射到已有本体，并验证、激活映射版本。
4. 在查询测试查看业务计划、严格 IR、参数化 SQL 和真实结果。
5. 在智能问答中询问金额、数量、排名等问题；数值必须来自成功执行的结构化查询并带数据引用。

模型和 Harness 不能提交原始 SQL，也不能获得数据库密码。

## 5. 发布知识应用

应用构建按以下顺序进行：

1. “知识供给”：组合知识空间并创建不可变版本。
2. “能力场景”：选择知识供给、模型、检索通道和引用策略，发布场景版本。
3. “上线测试”：用包含标准依据片段的真实业务问题运行检索门禁。
4. “接入发布”：给应用授予最小知识/场景范围并生成一次性显示的凭据。
5. “运行反馈”：将错误、过期、引用等问题转入治理工作台。

知识空间有新发布版本时，知识供给页面会提示“上游知识已更新”。应用不会静默漂移，管理员需创建知识供给新版本、重新测试并切换正式别名。

运行问题的完整闭环是：

> 应用反馈 → 治理任务 → 人工修正并重新发布 → 通过上线测试 → 选择该测试确认修复 → 反馈已解决

只有治理完成但未通过回归测试时，反馈状态是“待验证”，不能宣称已经闭环。

## 6. 日常运营检查

每天查看工作台唯一“建议下一步”和运营中心：

- 失败/长时间运行任务是否有可执行原因；
- 数据源是否按计划同步；
- 新文档是否已发布到当前知识版本；
- 低质量/OCR/ASR 问题是否进入治理；
- 知识供给是否落后于上游空间；
- 应用调用、反馈和上线门禁是否异常；
- 审计日志是否存在越权或敏感配置操作。

平台健康不等于业务知识正确。交付验收必须同时核对标准答案、来源引用、结构化数值和权限隔离。
