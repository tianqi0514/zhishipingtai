# UI/UX P0–P2 业务可用性收口

## 目标

本轮针对空数据和首次使用场景收口前端体验，不改变 Semantica、DeepSeek Harness、检索、治理或应用运行时的技术边界。目标是让管理员从空平台进入后能沿着“创建知识空间 → 接入内容 → 加工治理 → 检索服务 → 应用发布”的顺序工作，并确保页面上的主要按钮都有明确前置条件和真实后台能力。

## P0：阻塞性问题

| 问题 | 调整 | 验收标准 |
|---|---|---|
| 未选择知识空间仍可进入空间内操作 | 文档、数据源、治理、图谱、分析、检索统一使用前置条件空状态 | 页面只保留一个可执行下一步，不发起无效业务请求 |
| 空页面同时出现多个重复入口 | 空知识空间只显示“创建知识空间”；空文档显示“上传文档”和“添加数据源”；空图谱保留“上传并生成图谱”和“手工新增节点” | 主次动作清晰，无重复按钮 |
| 后台异常直接暴露技术信息 | 增加统一用户错误转换，模型连接和页面加载不再展示 API Key、认证头、原始 JSON 或长堆栈 | 页面给出可操作中文错误，敏感内容不回显 |
| 创建空间后流程中断 | 创建成功后自动切换为当前空间并进入文档列表 | 用户可以直接上传第一份文档 |

## P1：核心业务路径

| 模块 | 调整 | 保留的真实能力 |
|---|---|---|
| 应用构建 | 左侧菜单合并为“应用工作台”；知识供给、能力场景、上线测试、接入发布和运行反馈作为工作台下级步骤 | 原路由和全部 CRUD/API 保留；直接访问下级页时显示返回工作台和前置条件 |
| 多模态策略 | 适用媒介和基础信息默认可见；语音、视觉、抽帧和安全限制折叠 | 原有全部策略字段、校验、版本和复制功能保留 |
| 角色权限 | 逗号分隔的权限字符串改为按业务域分组的勾选矩阵 | 保存时仍生成后端现有权限码；未知扩展权限在兼容区保留 |
| 质量评测 | 期望片段 ID 改为按知识空间搜索并选择真实知识片段 | 使用真实治理目标搜索和片段详情接口，不允许以不存在的 ID 作为标准依据 |
| 应用步骤 | 每个下游页面检查真实上游产物 | 未完成知识空间、知识产品、场景版本或应用创建时，只显示对应的下一步入口 |

## P2：一致性与专业配置降噪

- 模型类型、模型供应商、组织类型、解析方式和权限使用中文业务名称。
- 模型运行参数、解析器专用参数、切片/抽取/治理扩展参数、本体命名空间与约束、图谱扩展属性默认折叠。
- 检索诊断和能力检测从主菜单移入运营/配置相关入口，避免与日常知识服务并列。
- 删除工作台、治理、媒体、模型路由和应用支撑页面中重复的 PPT 式说明，保留标题、状态和操作所必需的信息。
- 统一空状态、前置条件、权限矩阵、证据选择器和应用上下文条的视觉样式，并适配窄屏。

## 没有删除的能力

本轮只调整信息架构和交互层级，没有删除 API、数据模型或业务数据。被移出主菜单的诊断页仍可从运营中心或相关配置页进入；应用构建的五个下级页面仍保留原路由、真实接口和历史数据兼容能力。

## 验证范围

- JavaScript 语法检查。
- 静态 UI 合约：导航、空状态、前置条件、权限矩阵、证据选择、错误脱敏、配置折叠和响应式样式。
- Linux 容器内 Python 完整回归。
- 测试服务器无删卷部署、健康检查和错误日志检查。
- 真实浏览器对空数据主流程、配置弹窗、菜单收口、取消操作和常见桌面分辨率进行点击验证。

完整执行结果记录在本轮开发留痕与最终交付报告中。
