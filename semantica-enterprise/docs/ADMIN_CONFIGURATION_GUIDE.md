# 管理员配置指南

## 推荐配置顺序

| 顺序 | 配置 | 最小完成条件 | 验证方法 |
|---|---|---|---|
| 1 | 组织机构 | 集团、子企业和部门层级完整 | 用户归属可选且层级正确 |
| 2 | 角色权限 | 管理员、维护员、员工、应用开发者、审计员 | 非管理员左侧菜单与 API 权限一致 |
| 3 | 模型服务 | 默认 LLM 和 Embedding 真实可用 | 连接测试执行真实最小请求 |
| 4 | 解析/加工策略 | 每类策略只有明确默认项 | 新文档任务记录策略版本 |
| 5 | 知识空间 | 业务边界、负责人和授权完成 | 不同账号做允许/拒绝验证 |
| 6 | 数据源 | 连接、范围、增量和计划完整 | 手工同步、unchanged、变化版本 |
| 7 | 本体/映射 | 关键业务对象、属性和关系已验证 | 激活映射后执行只读查询 |
| 8 | 应用供给 | 知识版本、场景、门禁、凭据完整 | 外部令牌调用及撤销验证 |

## Secret 管理

- 模型 API Key 和数据源密码由 Secret 文件或加密字段保存。
- 前端只显示“已配置/未配置”，更新时留空表示保留原值。
- 应用 Client Secret 只在创建或轮换时显示一次。
- 不在命令、截图、日志和测试报告中记录明文。
- 正式部署必须替换 `.env.example` 中所有开发默认值。

## 权限原则

- 平台权限决定“能否使用模块”。
- 空间授权决定“能否读取或维护具体知识”。
- 显式拒绝优先于允许；无授权默认拒绝。
- 应用开发者只能管理自己创建的应用对象。
- FastAPI 在检索投影返回后仍会回查当前用户、空间、Chunk 和文档版本。

## 变更控制

- 文档、映射、规则、知识供给和场景都使用版本边界。
- 发布失败时保留旧的正式版本。
- 治理使用覆盖层并可回滚，不修改 Semantica 原始自动结果。
- 删除文档前必须等待解析和知识加工结束。
- 数据库 Schema 漂移影响主键、字段或关联条件时，必须先更新映射再恢复查询。

## 上线前检查

1. Docker 必需服务全部健康。
2. 冷启动迁移和持久卷重启均通过。
3. LLM/Embedding 连接测试通过；未配置的 Vision/ASR/Reranker 有明确降级。
4. 真实文件、扫描件、邮件、音视频和 ZIP 已做解析验证。
5. 数据源完成连接、同步、增量和错误重试验证。
6. 普通员工、维护员、应用开发者和审计员的权限均用真实账号验证。
7. 多轮问答、引用、取消、重试和刷新恢复通过。
8. 应用凭据的签发、调用、轮换和撤销通过。
9. 浏览器控制台和服务日志无未处理异常。
