# 知识分析浏览器点击测试

## 测试环境

- 地址：<http://localhost:8080/#analysis>
- 日期：2026-09-04
- 浏览器尺寸：桌面端主流程验证
- 数据空间：制度与供应链分析库、知识分析验收空间

## 已完成的真实点击

1. 登录并从左侧全局入口选择知识空间。
2. 进入“知识洞察 → 知识分析”，默认落在“分析任务”。
3. 打开“数据准备情况”，检查对象、关系、图谱版本、告警和真实关系词表。
4. 点击制度适用范围模板进入五步向导。
5. 修改任务名称和业务问题。
6. 查看当前空间真实实体类型、关系类型、数量与样例。
7. 查看业务角色编辑器和自然语言规则预览。
8. 执行真实试运行；界面等待后显示 4 条输入前提、预计 1 条结论和匹配样例。
9. 返回步骤并继续，确认输入状态未丢失。
10. 默认选择“预览结果”，点击“保存并运行”。
11. 在发现结果中观察真实任务百分比，等待 Worker 完成。
12. 打开推导结论，查看两条前提及证据缺失提醒。
13. 点击“加入知识库”，检查影响预览并确认提交。

该轮点击在补充 100% 来源证据的独立验收空间之前完成，因此页面正确显示来源证据不足，而没有伪装为可追溯。随后发布、撤回、来源片段、普通查询和 SPARQL 使用 live API 自动化完成回归。

## 静态与响应式保障

- `node --check apps/api/static/app.js` 通过。
- UI 合约测试覆盖默认业务页签、五步向导、功能说明、普通查询/SPARQL、业务术语和无技术标识泄露。
- 结果区、运行列表和证据详情使用独立滚动；分析卡片和双栏布局在 1320px、1000px、900px 设置断点。
- 弹窗继续复用已验证的隔离表单实现，取消操作不提交，保存期间防重复提交。

## 复测清单

部署后建议在“知识分析验收空间”做一次人工验收：

1. 制度适用模板预览后打开两条来源片段。
2. 加入知识库并从知识图谱确认推导关系。
3. 撤回本次发布。
4. 使用供应商风险模板验证三条前提。
5. 进入规则库查看版本前后对比。
6. 在专业查询普通模式按“适用于”查询，再执行内置 SPARQL 示例。

页面不得显示模型私有思维链、API Key、内部 Token、原始 UUID 或 proof JSON。
