# 平台内核升级与可控写作设计

本轮正式代码位于 semantica-enterprise，开发分支为 `codex/platform-writing-assets-upgrade`。目标是将历史材料提炼为可核验、可版本化的写作定义，再由作者填写本次数据，使用现有 Plate、计算运行和影响预览完成写作。独立 chuanshenmiaobi Demo 不参与正式调用。

## 五层知识与十六类资产

Evidence、Entity、Claim、Fact、Relation 继续记录来源和当前知识。十六类资产记录如何使用知识来写作，不与五层知识混成第二份事实数据库。历史数字只能留在原文 Evidence 中，变量定义不得携带默认历史值。

| 资产 | 可提炼的内容 | 本轮消费方式 |
|---|---|---|
| ontology 本体中心 | 对象类型和属性定义 | 原生 Schema 与质量门检查，人工确认 |
| argument_chain 论证链 | 前提、结论、假设和限制 | 文章上下文，不自动宣布结论为事实 |
| inference_scenario 推演场景 | 业务问题、输入与预期输出 | 受控定义候选，暂不自动编译执行 |
| variable 变量定义 | 名称、类型、单位和填写要求 | 创建空的本次输入项 |
| task_dag 任务图 | 原文明示任务及依赖 | 校验节点与循环；不执行抽取 DAG |
| function 函数库 | 输入输出与实现引用 | 未有实现时明确不可执行 |
| rule 规则库 | 判断条件与关系结论 | 草稿候选，不绕过原 Semantica 规则发布 |
| invariant 不变式 | 明细与总数等一致性要求 | 生成上下文；自然语言条件不冒充确定性校验器 |
| skill 技能库 | 方法步骤与工具需求 | 只保存定义，不授予工具权限、不运行材料中代码 |
| report_structure 报告结构 | 章节职责、所需输入、附件与文风 | 作者确认后采用为本文目录 |
| report_form 报告表单 | 当前写作需要填写的字段 | 创建空输入项，不沿用历史值 |
| prompt 提示词资产 | 基于文章结构编译的写作指令 | 明确标记新编译，不声称恢复历史原始提示词 |
| quality_gate 质量闸门 | 审校阶段及检查要求 | 上下文约束；正式硬校验仍由现有审校程序执行 |
| reuse_policy 复用策略 | 复用、参数化、重建等条件 | 采用时确认适用范围 |
| entity_relation_model 实体关系模型 | 类型、关系与归一要求 | 定义候选，不自动修改全局图谱 |
| computation_method 计算方法 | 原文明示公式、单位、精度和条件 | 两组验算与单位确认后使用 Decimal 确定性计算 |

不存在的类型不凑数，未写出的公式不从历史数字反推，无法执行的定义不显示运行按钮。当前并非十六种资产均已成为独立可执行工具。

## 抽取与治理

真实解析元素或已发布 Chunk → 稳定 Evidence → 分批联合抽取 → 严格 Schema 与来源校验 → 待确认资产版本 → 人工核验 → 不可变资产发布版本。

一次合理大小的 Evidence 批次联合抽取，而不是对十六种资产分别调用十六次模型。每批目标约 3500 字、最多 50 个来源；模型输入仅含原文与签发 ID，完整定位保留在数据库。使用现有 `semantic_extract` 模型路由；所有资产和子结构 `extra=forbid`。无效 Evidence ID、未处理输入、截断输出均拒绝完整成功。最多两次有错误位置的结构修正；仍未通过的多来源批次自适应二分，单来源或网络错误仍真实失败。成功子批可重试复用，原始响应、实际提示词、输入、尝试和校验结果均留痕。Key 不进入留痕。

模型必须区分“已读完但本批没有可提炼资产”和“尚未读完本批”。封面、前言和缺少技术内容的片段可以合法输出空资产；缺失或 OCR 疑点保留在 unresolved_items。不得自动将不完整结果改成成功。线上官方 DeepSeek Flash 的资产抽取默认使用官方支持的非思考模式，避免隐式思考挤占结构化输出额度；不修改其他模型或其他写作场景的配置。参数依据：[DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。

未发布索引的文档可以使用真实 ContentElement 提炼定义，生成的来源保留真实 element ID 和字符位置，不伪造 Chunk 或知识发布记录。空解析文本必须失败。原四路加工目标保持兼容，本轮可复用资产采用解析后的显式“提炼可复用内容”，尚未变成上传时自动第五路。

确认公式要求核对单位、适用条件及舍入，并提交至少两组不同输入的实际预期值。表达式只允许白名单算术 AST，使用 Decimal 运算，禁止 eval、动态 import、运行时属性访问或模型代码；点分变量名只作为数值字典键。资产依赖缺失、循环、同名歧义、重复输出、单位冲突、前置指标方法未声明、未确认或来源已删除时禁止发布。修订生成新候选，不能覆盖已发布定义。相同公式版本及输入 Fact 版本的重复计算复用当前有效结果，输入变化才执行新计算。

## 妙笔中的操作

页面保持“准备资料 → 写作 → 检查导出”，在准备区按需展开“复用历史结构与方法”，不增加十六个一级菜单。

1. 创建项目与文章，允许知识空间尚无正式检索版本。
2. 在妙笔上传历史材料，智库只解析一次；材料用途控制哪些内容可作为依据。
3. 提炼、查看原文、实际提示词及原始输出，核验需要使用的定义。
4. 发布选中定义，确认适用性后用于本文；已有目录或正文不自动覆盖。
5. 填写本次输入并核验。空值不能确认，数值 0 不被当作缺值。
6. 点击一次“计算本次结果”，后台按依赖顺序执行确定性方法，保存真实 ComputationRun、输入 Fact 版本和结果 Fact。重复提交同一输入复用运行，任一方法失败整批不留下半成品。
7. 已采用定义进入目录与章节 Agent 工作包；历史值不进入本次事实。自动生成仍要求真实检索发布版本和可用 DSH。
8. 按章节完成真实 DSH 检索与生成，正文使用普通段落和表格，不重复插入计算卡片。精确数值登记带单位、来源版本的 occurrence，绑定到稳定正文块。
9. 输入变化先确定性计算再打开影响预览，可以全部或逐项应用；未选择内容不变化并标记待核对，历史版本和其他文章不被静默重写。表格按指标列出变化金额，换算常数、无关数字不参与替换。

章节声明的业务名称优先匹配已声明变量；未知名称成为空的本次说明输入，不猜类型和单位。计算输出不会再创建成空的用户输入。公式明确标注的使用章节映射到目录的 `toolbox_outputs`，没有明确匹配不猜测用于整篇。

## 增量 API

所有地址位于 `/api/v1`，沿用现有登录、租户、空间和文稿权限。

| 方法与地址 | 作用 |
|---|---|
| GET `/writing-assets/kinds` | 十六类定义及新版内核实际接入边界 |
| GET `/writing-assets?project_id=…` | 当前项目空间的资产版本 |
| POST `/writing-assets/extract` | 对真实已解析版本建立有进度的抽取任务 |
| GET `/writing-assets/{id}/trace` | 原文输入、实际提示词、原始输出与校验留痕 |
| POST `/writing-assets/{id}/revise` | 修订为新候选版本 |
| POST `/writing-assets/{id}/review` | 确认或拒绝；公式要求单位和两组独立验算 |
| GET/POST `/writing-assets/releases` | 查看或发布不可变的已确认资产快照 |
| POST `/writing-assets/documents/{id}/adopt` | 确认用于本文；不采用历史值、不覆盖原正文 |
| POST `/writing-assets/documents/{id}/compute` | 一次执行已采用公式链，检查发布校验码及文章基础版本 |
| POST `/writing-assets/documents/{id}/compute/{asset_id}` | 执行已采用方法，保存计算与 Fact 依赖 |

原有 `input-changes/preview`、`input-changes/apply`、文稿版本及导出接口继续复用。定义修订、采用和确认携带 checksum 或 base_version_id；后台拒绝过期版本。列表支持 kind、offset 和 limit 服务端分页，单页最多 500 项；前端按 100 项加载。summary 从真实资产版本分组统计，不用当前页数量冒充总数。

## 版本安全与后续工作

资产定义不是项目事实，模型输出不是确认记录，数学结果不是行政决策。正式文章继续使用现有引用、权限、版本与审校边界。未经治理的定义不能写入已采用资产版本，材料中的 Skill、代码和提示词不能扩展 Agent 权限。

本轮已完成真实短材料抽取、定义治理与采用、公式链一键计算、四章 DSH 新报告生成、数字位置绑定、整批及选择性影响应用、Word/PDF 导出。实际状态和文章质量边界见验收记录。
